# The game server's replays and its own matches of computer players

This page is the part of [`SERVER.md`](SERVER.md) that belongs to the matches that the server keeps as replays and to the matches of computer players that it plays itself.

## Replays

The server keeps the matches that its rooms play, so that they can be watched again ([`REPLAYS.md`](REPLAYS.md) says what a replay is and what plays it). The referee's own runner is watched while the match runs (it changes no hash), and when the match is over the file goes to a folder of the results volume (`replays` in `--results-dir`; `--replays-dir` chooses another folder and `--no-replays` keeps none). The numbers of the replays are here; the other documents point to this section.

- **What is kept.** A match that ran at least 600 turns (30 seconds), however it ended: the rules ended it, a player quit, an operator closed the room, its time limit, a desync. A shorter match is not kept, so rooms that start and are closed at once leave nothing; the room's status says why (`replay.note`). A longer match whose recording failed is not kept either: the note says why (a recording is limited to 1 MiB, for one) and the log has one line. Demo rooms are kept with `--replay-demo` (the stack file has it; a demo room is a room that a visitor's create block made, the games of the front page, and never one that the control interface made), and a room of the control interface may say `"record": false`. A solo game in a browser tab is not played on the server and is not kept. When the server is stopped, a room that holds a restart record stays in the record and is not saved now, and a match that the server brought back from a record is not recorded from then on (the recorder did not see the part of it before the restart); any other room is closed, and its match is kept like that of a room that an operator closed.
- **Names.** A person's seat keeps the name that the room showed everybody, the name that the player typed: plain ASCII (the letters from the space to the tilde; every byte of anything else becomes a `?`, so a letter with an accent, which is two bytes, gives `??`), at most 32 characters, the blanks at both ends cut (`replay_person_name` in `room.hpp`). The readers show it after the color, "Green (Ann)". A seat with no name of its own shows the color alone, "Green": nothing was typed, or only the words that the game itself uses for a player without a name, "Player" and "Player 1" to "Player 4" (a name that only starts like them, "Players" or "Player 5", is a name and is kept). A computer player's seat has its display name, "Bot (Easy)", "Bot (Medium)" or "Bot (Hard)". The front page plays a visitor who is logged in under the login's name and any other visitor under a guest name ("Guest" and six digits); both are kept like any other name. **The names are public wherever the public door (below) is on, which it is in the stack file:** anybody can read them in the list and in the file, so a page that shows them must show them as text. No address, room code, key or chat is in a file or in the list. The file's name is the map and the time the match ended: `ants-TREASURE-20261008-143209Z.antsrep` (UTC; `-2`, `-3`, ... when two matches of a map end in one second).
- **The notice on the pages.** A line says what the server does with an online match. The front page shows "Online matches are recorded. Recordings are kept for 30 days. Results and names are kept for good and are public." in its footer and under the name field of the card that a shared link opens (the element `who-notice`); the game page's name card says "Online matches are recorded. Anybody can watch them, live or later. Recordings are kept for 30 days. Results and names are kept for good and are public." (not in the step of a game on this computer: the server does not record that game). The pages are static, so the line is true only for a server that runs as the stack file runs it: `--replay-demo` (the front page's matches are kept), `--replay-port` (the public door below, which the site's nginx passes `/replays` to) and 30 days (`--replays-days`, `ANTS_REPLAY_DAYS`). A server with other settings (`docker-compose.server.yml` has the first two off) changes the words in `web/lobby.html` and `web/shell.html`, and leaves the element `who-notice` of the first where it is.
- **Only its own files.** The server touches nothing in the folder but files with a name of that form: another file is left alone and is not counted. A file is written whole under a temporary name and renamed, and an existing file is never replaced, so a crash of the server leaves a whole file or none (a power cut may leave a short one: the operator's list shows it as unreadable, and it goes when it is old). A name is looked up in the server's list, never opened as a path. When the server starts it reads every file once; after that nothing takes longer than one small file write, one pass over the list or one look at the folder (a `stat` for every file, and the reading of at most 100 new ones). A file that somebody else puts in the folder (`bot_arena --save-replays`, [`REPLAYS.md`](REPLAYS.md#matches-of-computer-players)) is listed within half a minute: every 30 seconds the folder's change time is looked at, and only when it moved (or moved a moment ago) is the folder read again (at most 100 new files at a time; a file that changed in the last two seconds waits for the next look, and a known file is read again only when it could not be read or its size moved); a file that was taken away is forgotten and nothing is deleted for it, while a file that came from outside is under the limits like any other (one older than the keep time is deleted at once). A file of the store is "never replaced" by the store itself; another program that writes into the folder with the same name in the same second could replace it (a rename replaces on Linux), which is why only one writer is meant to run at a time ([`REPLAYS.md`](REPLAYS.md#matches-of-computer-players)). Opening the folder deletes the `.tmp` of a crash but not one that changed in the last two seconds, which is the write of the other program.
- **How long and how much.** A file is deleted `--replays-days` (30) days after its match ended, and all the files together stay under `--replays-max-mb` (100 MiB), the oldest first. The limits are applied when the server starts, before every file is written (so that the new one fits) and once an hour. The age of a file is the time in its name, so it is as right as the server's clock: a clock that jumps ahead by 30 days deletes the files at the next look, and one that is set back files new matches among the older ones and starts the hour's allowance again.
- **A full disk never stops the server.** The folder shares a volume with the control secret and the restart records, so the server keeps nothing new when the disk would be left with less than 256 MiB free, or when it has kept 120 matches in the last hour, and a match is 1 MiB at the most (2 MiB with a map). The log tells a refusal once and counts its repeats: one line when another line follows, once an hour, and at the stop. The allowance does not tell people from scripts: one 30-second match after another can use it and the 100 MiB up, so the oldest files go first.
- **The public door.** `--replay-port N` opens a second door, read only, with no secret: `GET /replays` gives `{"replays": [...], "count", "keep_days", "sim_rules"}` (the last is the rules number of this server's build for the original's game, 9; a 187 match has 12 and its entry says `"mode": "187"`; the site's list page shows the files that this build plays (the original's game 5, 8 or 9; 187 6, 7, 10, 11 or 12) to watch and the others as older versions, [`REPLAYS.md`](REPLAYS.md#the-file)) (the newest 200 files that this build can read, each with the fields of the control interface's entry except `readable`; `count` is the number of such files, not of the 200), `GET /replays/<file>` gives the file of one of them, and everything else is 404 (any other method is 405 with `Allow: GET`, a request with a body is 400 for a plain `Content-Length`, 411 for a chunked one, 413 for one that is too large and 417 for an `Expect` that is not `100-continue`, and `GET /healthz` is answered by the server itself as on the control port). It is off unless the option is given (the program's own default). **`docker-compose.stack.yml` gives it, on port 4020 of the container (not published on the host): the list and the files of the stack's site are public, and so are the names of the players in them (Names, above).** `ANTS_REPLAY_PORT=0` switches it off; leave any other value alone, because the nginx of the site passes to 4020 only (a server that listens elsewhere looks like one without the door: the site answers 404).
- **Live matches.** The same door shows the matches that run now ([`REPLAYS.md`](REPLAYS.md#on-the-game-server), "Live"): `GET /live` and `GET /live/<id>`, the same rules as the rest (GET only, a query is 404, no secret, nothing from a request is ever made into a path). A room that records its match puts it on the *live board* (`live_board.hpp`, owned by the room manager next to the replay store) when the recording begins and takes it off when the recording becomes a file or is dropped; the board holds a pointer to the room's recorder and nothing else of the room, and the room takes the match off before the recorder goes (a closed room, a match that ended, the manager's destruction). So a room that does not record (`"record": false`, no store, a match brought back from a restart record) is not on it, and neither is a match played with Fog of War (a live view would show what the fog hides from its players; the site offers no fog, and the match is public when it is over like any other).
  - **The list**, `GET /live`, is `{"live": [...], "count", "sim_rules"}`: the matches that ran at least 600 turns (30 seconds, the length the store keeps) and whose recording has not failed, the newest start first, **50 at the most** (`count` is the number of entries listed). An entry is `{"id", "map", "mode", "started", "turns", "seconds", "players"}`: `mode` is the match's game mode in the words of the list of games and the history (`"highest-score"` or `"187"`), `started` is seconds since 1970 UTC, `seconds` is the turns divided by 20, and `players` are the strings of the replay list ("Green (Ann)", "Green", "Red (Bot (Medium))": the names of "Names" above, public here too). The `id` is `<MAP>-<YYYYMMDD>-<HHMMSS>Z`, the stem of the map's file name (letters, digits and `_`, 24 at the most) and the UTC second in which the match began, with `-2`, `-3`, ... when two matches of a map began in one second; it holds nothing of the room (no code, name, address or key), and it is all a visitor can ask for.
  - **The snapshot**, `GET /live/<id>`, is 200 `application/octet-stream`: the match so far as an incomplete replay file (no `ENDS` chunk) with one more chunk, `live`, that holds the turns run when it was made ([`REPLAYS.md`](REPLAYS.md#the-file)), so that the code that plays a replay plays it up to that turn. **There is no delay, on purpose.** Only a listed match has one (the list's rule), and it is made with `Recorder::snapshot`, which changes nothing in the recording. It is made again at most once a second for a match, however many watch it (the board keeps the bytes for as long as its clock stays in the second in which they were made), so a crowd costs one encode of at most 1 MiB a second for each match that is watched, and the same bytes go to all of them.
  - **When it is not there:** 404 with `{"error": "no such live match", "ended": false, "replay": ""}`. For 15 minutes after a match of at least 600 turns has ended (at most 256 matches are remembered, the oldest forgotten first) its id answers `"ended": true` and `"replay"` is the name of the file that the store kept it as (`""` when it was not kept, or when the file is no longer in the store), so that a page that watched finds the replay. Every other failure of a `/live/...` request has the same body with `"ended": false`: a method other than GET, a query, an id of another shape (checked before any lookup), an id that is not on the board, a server without a replay store. `GET /live` itself answers 404 `{"error": "not found"}` for a method other than GET, a query, or a server without a replay store.
- **The match history.** The recordings go after `--replays-days`; what the matches came to stays, in the database ("The database", [`REPLAYS.md`](REPLAYS.md#the-match-history) says what a record holds, who won by the rule of each game mode, a draw, and the states of the recording). Three tables (migration 2): `history_matches` (one row for each match, with a column and an index for everything that the list filters or sorts by), `history_seats` (one row for each seat) and `history_markers` (the matches that an operator deleted while their recording is kept). The id is the recording's file name without `.antsrep`. Nothing is counted while a match is played: the feeder in `RoomManager::update` plays the recordings of the replay store once more, one at most every 250 ms and only while no room runs or loads a match and none is being restored, the newest first, and adds the record in one transaction. A recording takes 0.4 - 0.5 s to count for a match of 10 - 12 minutes (more for a longer one), so the gap after it is counted from the END of the work and is at least 250 ms and four times what the work took: the main thread is free most of the time; the recordings found when the server starts, up to 30 days of them, are the backfill, and a file the arena puts in the folder is found by the replay store's look every 30 seconds and counted like a room's own match. The same play counts the stats of the record (`details`, [`REPLAYS.md`](REPLAYS.md#the-match-history): 1 to 3.5 KB at most 5,000 bytes), and, when no new file is left, a backfill gives them to the records that were counted without (the rules are in `REPLAYS.md`). The same play finds where each lost ant stood, kept in `history_deaths` for a match counted here only (no backfill). The match's map is looked for in the maps folder and then in the community folder (`--community-maps`), the first that holds the name being the map's, like the lobby's list. A recording that cannot be counted (a map that is missing, a map of the same name that is another file, a file that does not play out) is left out and told in the log, the first ten by name and the rest in a summary; one of other simulation rules is not played and only counted in the summary. **Everything happens on the server's one main thread** (SQLite is built without mutexes); the work of a pass is one recording and one transaction. **A database that stops answering never takes the server down and never touches the match path:** the first error is logged once, the history is *unavailable* (the routes answer 503 with a clear body, and the feeder waits), it looks again every minute with a cheap read, and the log says once when it answers again; a record that the database refuses as such (a constraint) is told in the log and left out for this run, and the history stays available. **A list is time boxed and paid for:** a visitor's list is stopped by the database (`sqlite3_progress_handler`) after 15 ms of wall clock and answers 503 `that search is too heavy for the server: narrow it`; the operator's box is 100 ms. The public door has a *budget* on top, a token bucket of milliseconds of query time (100 ms in a burst, 50 ms earned for each second, each list paid for by the time it took); when it is empty a list with a query is a 503 `the match history is busy: try again in a moment` at once, without touching the database. **The list without any query is not held back by the budget** (it keeps the 15 ms box; it takes under a millisecond and the site's nginx keeps it for five seconds, serving the old copy while the server says 503), so a flood of heavy searches cannot lock the page's own list out; a match by its id is no list and has no budget either. So the public door can take about 5 % of the main thread whatever the number of visitors. A request's words never become SQL: a statement is made of fixed pieces and every value is bound; the search `q` escapes `%`, `_` and `\` so that a name is found as typed. An operator takes a match out with `DELETE /history/<id>` ("The control interface"); the server never deletes a record by itself. `GET /history` and `GET /history/<id>` are on the public door too, with the same rules as the rest (GET only; the list takes the query of its filters, every other query is 400 or 404; nothing from a request is ever made into a path), and the names in them are public for good. A writer outside the server (a tool run on the file while it runs) makes a write wait for the database's busy timeout (5 s) at the most; the history is written only while no match runs.
- **The site's nginx** (`docker/nginx.conf`) passes `/replays` (an exact location) and `/replays/<file>` (a prefix location) to that door, like `/busy`: GET only (405), no query (404), a file name of the wrong shape is 404 at once (the store decides which names exist), and nothing of the visitor's request but Host and Connection is passed on. The allowances count each visitor's address (behind a reverse proxy that ends TLS, name the proxy in `docker/trusted-proxies.conf`; the image's list names one at a private address, [below](SERVER.md#behind-a-reverse-proxy)): 20 requests a second for the list with a burst of 100, and 10 a second for the files with a burst of 20 (503 beyond), one zone each. The list is cached for five seconds for everybody (an entry of its own in the cache of `/stats`), so a crowd of visitors asks the server about once in five seconds; a file is asked of the server each time. Timeouts are 3 seconds to connect and 10 to read and send. The server's `Cache-Control: no-store` still goes to the browser. When the server has no such door, or is not there, the site answers `404` with `{"error": ...}`, never a 502 page. `/live` (an exact location) and `/live/<id>` (a prefix location) go the same way, with the same checks (an id of the wrong shape is 404 at once: `[A-Za-z0-9_]{1,24}-[0-9]{8}-[0-9]{6}Z(-[0-9]{1,4})?`) and the same timeouts and fallback, but with allowances of their own, so that a crowd that watches does not use up the downloads' (a page asks for the list every 10 seconds and for the match it watches every 4): 20 requests a second for the list with a burst of 100 and 30 a second for the snapshots with a burst of 60 (503 beyond), one zone each. **Both are cached for two seconds** (the list in one entry, a snapshot in one entry for each id, in the cache of `/stats`, which holds 8 MB; only a 200 is kept, so made-up ids fill nothing). An entry that is being renewed is served old, but not one when the server does not answer: a snapshot that is repeated for minutes looks like a match that goes on, and the 404 is the truth. So the server is asked about once in two seconds for each match that is watched, on top of its own snapshot of one second. `/history` (an exact location) and `/history/<id>` (a prefix location) go the same way too, with allowances of their own (`ants_history`: 10 requests a second for a list without a query with a burst of 50; `ants_history_query`: **2 a second for a list with a query, a burst of 5**; `ants_history_deaths`: 2 a second for `/history/deaths`, a burst of 5, its answer kept 30 seconds; `ants_history_items`: 20 a second for single matches with a burst of 40; 503 beyond), a GET only (405), an id of the wrong shape or a query on a match 404 at once, and a list query of the characters that the filters are made of and 400 characters at the most (400 otherwise). The list without a query is cached for five seconds, in one entry for everybody, an old list served while a new one is fetched and when the server does not answer; a list with a query is cached for five seconds too, one entry for each distinct query, in a cache of its own (`ants_history`, 8 MB), so that made-up queries cannot fill the small cache of the numbers; a match is asked of the server every time. `/lobbies` ([above](SERVER.md#lobby-rooms)) goes the same way as `/live`, with the zone `ants_lobbies` (100 a second, burst 200, for each address as above) and a read timeout of 3 seconds; without the door it answers `404` with `{"error":"lobbies_off"}`.
- **In the log** the line of an ended room ends with `, kept as <file>` when its match was kept. The start prints where the replays are, for how long and how much, and (with the door) `public replays on port N` (the line names the routes, the live ones too).

### Matches of computer players

With `--bot-match-every-min N` the server plays a match of its own every N minutes, so that the site's list of live matches ([`REPLAYS.md`](REPLAYS.md#matches-of-computer-players)) is not empty when nobody is playing. The match is a room like the others whose seats are all bots (`RoomSpec::bots_only`; the control interface cannot make one, and such a room is no lobby and no public room and holds no seat): two to four standard bots, Medium or Hard each, on seats chosen at random and with a random seed, in the original's game or in 187 ([`GAMEPLAY.md`](GAMEPLAY.md#187-a-game-type-of-the-remake); a fair coin for each match, drawn after the others and with no memory of the last match, so two or three of a kind in a row come up), on a map of the list of those rules (each map of a list as likely as any other), and free for all or in teams. **The lists** (the tables `bot_match_maps` in `room_manager.cpp` are their one home): the original's game has nine maps, TINY, SMALL, MEDIUM, GAUNTLET, TREASURE, ISLANDS and three of the library, `POPcOrN.lvl`, `HELLRAISER.lvl` and `Bombz Away.lvl` (the community folder, `Community-Maps/`); 187 has six, TINY, SMALL, MEDIUM, GAUNTLET, TREASURE and `Fight Island.lvl`, an approved map of the players (Extended, 150 x 150, four hills). A 187 match is never on ISLANDS, whose water joins no two hills by a walk, so nobody could be struck there ([`BOT_187.md`](BOT_187.md)). The approved map is found as a lobby finds one, in the store of the approved maps ([`MAP_SUBMISSIONS.md`](MAP_SUBMISSIONS.md)), so a server whose door for the submissions is off (`--submit-port` 0) has none, and neither has one that took the map down. A map that the server does not have or that a room cannot play (this engine cannot load it, it is over a limit of the online size, or it has no place for four seats) is skipped: the others of the list are as likely as before, the log says `bot match: the map NAME is skipped (reason)` once (and again if the map comes back and goes), and no match fails for it. For the bots that play, free for all and each way to make teams are equally likely: with four bots one of the three ways to split them in two teams of two (on TINY, SMALL, TREASURE and ISLANDS, whose hills sit at the four corners of a rectangle: top against bottom, left against right or across the corners; MEDIUM's hills sit north, east, south and west and GAUNTLET's along a diagonal), with three bots any two of them as a team against the third, and with two bots only free for all (a team of both would be the whole match), so about half of all matches are teams. The room has the teams as its own, so they are made before the first turn like a room's teams in the create block ([`NETWORK_PORT.md`](NETWORK_PORT.md#the-room-code-is-only-a-name-and-the-create-block-makes-the-room)), the replay's head has them, and the live view and the replay play them. It is played at the normal speed, so it lasts as long as the map's own time limit (6 to 20 minutes on the maps of the lists: [`GAMEPLAY.md`](GAMEPLAY.md)) unless the rules end it sooner, and it is kept like any other match. The room's own limit is 25 minutes, or five more than the map's own when that is longer.

The first match begins a minute after the server starts, the next ones N minutes after the one before began. While a match of this kind still goes on, the timer makes no other, and it makes none when the server keeps no replays (a match that nobody could look at again). The log says each time what it did (`bot match: room CODE started (187)`, with `(highest-score)` for the original's game, and `bot match: not started (the last one is still going)`). A room without a person is not closed for "everybody left", a stopped server ends it, and a restart brings no record of it back (it holds no seat). It is no game that anybody played, so the site's statistics (`/stats`) do not count it, and `/busy` counts no match for it (a restart may interrupt it). The page of the list says that the computer players "start one every hour", which is the stack's default of 60.
