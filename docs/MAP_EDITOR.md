# The map maker (the editor page)

A page of the site, `mapmaker.html`, where a player makes a map, opens one from their own computer, looks at it, checks it and saves it. It is built on the map core that runs in the browser ([`MAP_FORMAT.md`](MAP_FORMAT.md), "In the browser"): the page never judges a map itself, it shows what the core answers (the check, the limits, the refusal of a size) in the core's own sentences. This page says what the editor is, what each of its pull requests does and which are done.

## The rules of the editor

- **Two kinds of map.** A **Classic map** works in the original game and in the new version (a new one has at most 90 rows, 130 columns and 10,000 cells). An **Extended map** works in the new version only (at most 512 x 512 cells, and no side longer than 1,024); it wears the quiet blue-grey badge "New version only", which is a note and not a fault. The numbers on screen are the core's (`limits()`), never a copy in the page.
- **Nothing is ever written over.** Making a copy, starting an Extended map from a Classic one (any Classic map, the game's library maps too) and saving always make a **new** map under a name that is free; the name of a library map or of a draft that exists counts as taken. The page has no way to open a file for writing: the only thing that leaves it is a download, which the browser saves as a new file.
- **Everything stays on the player's own device.** From E5 on, a draft is kept in the browser; the finished file is downloaded (E1 already does that). Sharing a map with other players is a separate, later piece of work and is not part of the editor.
- **Rows and columns count from 0**, as in the checker's sentences ("row 12, column 40"), so a "Show me" link and the position line say the same numbers.

## How the page is made

All of it is static files: `web/mapmaker.html` and, in `web/front/`, `mapmaker.css` and the scripts below (each a plain script that a page and node can load). The page loads the core's `lvl_core.js` and `lvl_core_api.js` first and the app last.

| File | What it does |
|---|---|
| `mapmaker_file.js` | Reads the grid and the markers out of the bytes of a file (version 8 and version 9) for drawing, where they are, without copying the cells; names a download. It judges nothing. |
| `mapmaker_tiles.js` | The color that stands for a tile: a few kinds of ground and of object, and the four teams. They are not the game's pictures (those come later). |
| `mapmaker_palette.js` | The eight tools (which paint with a brush, which put a whole thing with a tap, their letters), the four teams with their colors, the tiles that the palettes of Ground and Objects offer (the name on the screen, the game's own name of the tile from the list of `lvl_tile_names.inc`, and its color), and the 29 bigger objects with the cells that each covers. |
| `mapmaker_solid.js` | Which tiles are solid: the tile flag 0x01 of each of the game's 1,344 ids (`movement_tables_data.inc`), as a short table; and which of them own the solid bit of the cells they stand on (all but the hills). |
| `mapmaker_objects.js` | A bigger object put on a cell as a CHANGE (the cells of layer 2, the solid bits of layer 1, the name for the dictionary), without touching the bytes; what is in the way (a hill, starting ants, a food pile) is refused with a sentence. |
| `mapmaker_edit.js` | The editing, as arithmetic on the bytes of the open map (they are the one copy of the map): the brush, the line between two cells, a stroke, fill, the removal of a whole object, the solid bit that goes with an object, the name a tile needs in the dictionary, a change of `mapmaker_blocks.js` or `mapmaker_objects.js` as one step, and the history of patches (cells and splices). |
| `mapmaker_blocks.js` | Hills, starting ants and food piles: the lists after the layers (block 1 and block 2) read where they are, and a hill, a team's ants or a pile put or taken away as a CHANGE (the cells of layer 2, the splices of the bytes, the names for the dictionary) that `mapmaker_edit.js` applies. It touches nothing itself. |
| `mapmaker_view.js` | Where the map is on the screen (the point in the middle and the size of a tile): pan, zoom, the visible tiles, and the drawing: one rectangle for each visible tile, or, when a tile is under 5 pixels, one lookup for each pixel of the canvas. The small map is made once for a file. |
| `mapmaker_sizes.js` | The limits as the cards say them, the live line (cells and file size), and the core's refusal of a size turned into the sentence of the picture. |
| `mapmaker_checks.js` | The checks card: the core's `checkMap` answer, with its sentences shown as text. |
| `mapmaker_dialog.js` | The dialog box (focus, Escape, the page behind it inert) and the dialogs: New map, checks, messages, the phone's menu. |
| `mapmaker_canvas.js` | The hands: pointer, wheel, keyboard, the zoom buttons, the small map; with a painter, a mouse or one finger paints (or, for a tool that puts a whole thing, a tap puts it and a drag looks around), and only the cells that a stroke changed (and those under the marked square) are painted again. |
| `mapmaker_tools.js` | The tools in the page: the chosen tool, the palette (tiles, or the team and the number of ants, or the stages of a pile), the brush, Fill, Undo and Redo, the keys, and the painter that the canvas calls. |
| `mapmaker_app.js` | Starts the core, holds the open map, joins the parts: the check after a change, the question before a map that was drawn on is left, Download. |

A map is read as a place that takes both kinds reads it (the core's profile `extended`), so a library map and an Extended map open alike; the limits of a **new** Classic map are those of the profile `new_map`.

**How drawing works.**

- **One copy of the map.** The bytes of the open file are the map: a stroke writes the words of the cells into them in place, the canvas reads them there, and the check and the download hand the same bytes to the core. There is no second model of the level to keep in step.
- **A stroke is a patch.** The first time a stroke touches a cell it notes the cell's three words (tile, flags, third word); when the stroke ends, the cells whose words differ go to the history as a patch (a key, the words before and the words after: 16 bytes a cell, so a brush of 9 is at most 81 cells, about 1.3 KB, on a map of any size). Undo and redo apply a patch backwards and forwards. The history keeps at most 200 strokes and 400,000 changed cells (the newest stroke is always kept), and the page asks before a map that was drawn on is left (closed, reloaded, replaced by New or Open) unless it was downloaded as it is, because nothing is kept in the browser until E5.
- **What a stroke writes.** Ground changes the tile of layer 1 and keeps the cell's other words. An object is a layer-2 cell with flag 1 (the origin) and the anchor of its kind: itself, as row (low byte) and column (high byte) in a version 8 file and as the offset 0 in a version 9 file ([`MAP_FORMAT.md`](MAP_FORMAT.md), "Version 9"). The Objects tool (a tap, a brush, Fill) never takes a hill, a team's starting ants or a food pile away: a brush that touches one is refused as a whole, with a sentence ("Blue’s hill is here. Move it first, or take it away with Erase."), and nothing changes. The palette of Objects holds only objects that stand on one cell (a hill, a team's ants and a pile have their own tools, and so have the bigger objects, below). An object whose tile is solid also sets the **solid bit** (bit 0 of the flags of layer 1) of the cell it stands on, as the original does when it puts an object, and whenever an object goes (the eraser, an object that takes its place, a pile taken away) the bit of every cell it leaves empty is cleared, whatever the tile (the library has bombs, plants and other tiles that are not solid in the game's table and stand on cells that carry the bit), except in row 0, whose bit the original never clears: the remake reads that bit from the file and from nowhere else, so a rock without it would not block ants and a power-up without it would do nothing. A hill's bits are left as they are. Fill works for one click, then is off again; it paints the ground of the same tile round the click, or the empty cells round it with an object (it does not fill over objects). Erase and a new object take a bigger object away whole (the cells round its anchor that hold its tile and name that anchor), so a hill is never left in halves.
- **The dictionary.** A tile that the file's dictionary does not have is refused by the checker, and a name of "." is a tile that the original game does not draw. Before a stroke uses a tile the page gives it its name (the game's own, from the table of `mapmaker_palette.js`, which the tests hold to `src/ants_assets/lvl_tile_names.inc`) and, when the dictionary is too short, makes it longer by the names between; it never shortens it (a name that stays after an undo is harmless, and E5's save will write the dictionary by the rule of [`MAP_FORMAT.md`](MAP_FORMAT.md), "The dictionary of a new map").
- **Painting only what changed.** After a stroke the canvas paints again only the cells that changed and the ones under the marked square before and after (a tile of 5 pixels or more: its own rectangle and grid lines; smaller: its pixels in the picture that the last whole frame kept); a frame that would paint more than 3,000 cells, or a view that moved, is painted whole. The small map is made again once the stroke ends. A stroke also ends when the browser loses its pointer (a button let go outside the window, a lost capture, a window that loses the focus, a hidden page), so undo and the tools never wait for a stroke that is over. A Fill over a whole 512 x 512 map holds the page for about 0.35 seconds (about 0.65 seconds with the processor six times slower) while it writes 262,144 cells and paints once.
- **Hills, ants and food** (E3a). A tap puts the whole thing and a drag looks around (they are tools that put, not paint: no brush, no Fill). Each is a CHANGE that `mapmaker_blocks.js` works out from the bytes as they are, and `mapmaker_edit.js` applies as one step of the history, the same history as the strokes.
  - **A hill** is the 4 x 4 cells round the cell that was tapped (one row and one column before it, two after), the tile of the team's hill on layer 2, each cell anchored at the tapped cell, which is the entrance and the only one flagged: the shape that the checker calls whole ([`MAP_FORMAT.md`](MAP_FORMAT.md), the original-safe profile). In a version 8 file the anchor is the absolute row and column, in a version 9 file the offset to the entrance. A team has one hill, so putting it again takes the old one away; an object under the new one goes whole, but another team's hill is never taken away: the page says whose hill is in the way and puts nothing; there is no hill with its entrance at the top or left edge or in the last two rows and columns (a plain sentence says so). The square under the pointer is the 4 x 4 cells with a dot on the door.
  - **Starting ants** are the records of block 1 whose tile is the team's start marker, one for each ant; the original starts one ant for each record. A tap puts the chosen number (1 to 64; the library's maps have 1 to 62 for a team) on the cell and the nearest ones, passing cells with an object, solid ground or another team's ants (on a map with fewer free cells the line under the palette says how many fit), and takes the team's ants that were there away; the plants and the other teams' records stay as they were, in their order.
  - **A food pile** is a record of block 2: the cell, the bites (`units`), the points of a bite, and the stages: the game's own kinds, by the number of stages (2 to 6: the pile shows the tile of the last stage whose number is not below the bites that are left, and the last stage, the empty tile, makes it vanish when it is eaten; a pile of one stage could not be eaten, so there is none). A pile put on a pile replaces it.
  - **The eraser** takes, besides an object, the start of a team whose ant is on the cell (all that team's ants, together), and a pile whose cell, or whose object's body, it is; with the cells of layer 2 that show the pile. One drag is one step.
  - **Splices, not copies.** The records are in the file after the layers, so a change is `{rel, removed, inserted}`, the smallest piece of the file that differs, counted from the end of layer 2 (which does not move when the dictionary grows). A patch of the history holds its cells and its splices (the bytes that went out and came in, never the file); undo and redo apply them backwards and forwards, and a splice weighs a record for each 16 bytes in the bound of the history. A list that does not read where the count says (a file cut short, a pile without stages, where the original stops reading the food) is not changed, and the page says so; everything else of the file stays byte for byte. The tiles that these use are named in the dictionary first, which grows when it is short (the hill's tile 245 to 248, the start marker 152 to 155, the food tiles).
- **Bigger objects** (E3b). A tap puts the whole object; a drag looks around (a tool that puts, like Hills). The library's maps show how a bigger object is encoded: the **same tile on every cell it covers** on layer 2, every cell anchored at one cell (the origin, the only one flagged, which is also the cell that is tapped), and the solid bit under each cell. The Erase tool already takes such an object away whole (the cells round the anchor that hold its tile), so it needs nothing of its own. The footprints are measured, not guessed: a tile is on the list when it stands on more than one cell in at least 30 of the 540 maps (never a hill, a bomb, a power-up, food, or a plant of the flower droppers, which have tools of their own or come later), most used first, and its footprint is the one that the maps have most often (for 27 of the 29 it is also what the game computes from the sprite, `object_footprint.cpp`; for `can1` and `sling` the maps have one cell less, and the maps win). Each chip of the sheet draws the shape (a small square for each cell of its box, filled where the object stands, the anchor outlined), says the number of cells and the size ("10 cells, 5 x 2": columns by rows) and, as a small caption, the game's tile name (`grass4`, `grassmed1`, `bearbod`). `mapmaker_objects.js` works the CHANGE out from the bytes as they are: the cells of the footprint (those off the map are dropped, as the original drops them; the anchor stays on it), each anchored at the origin in a version 8 file (absolute) and in a version 9 file (the offset to the origin, so a map that grows keeps its objects whole), the solid bits, and the name for the dictionary. An object under the new one goes whole, never half of it left; a hill, a team's starting ants and a food pile (its cell, or the object that shows it) are never taken away without being asked: the page says "A hill is in the way" and puts nothing. The same object put on the same place changes nothing and is no step of the history. The canvas marks the object's box round the cell, with a dot on the anchor.
- **On a phone** there is no room for the palette beside the map: every tool that has a palette shows one button (the chosen tile; the team, with the number of ants; the stages) that opens the same choices as a sheet with their names (the Bigger tool has its list of 29 only as that button and sheet, on a desktop too: there is no room for so many beside the map), and the steppers (the ants, the stages) are 44 pixels each way. Held upright the page scrolls when the screen is too short (the map keeps at least about 190 pixels); held sideways the tools sit in two columns and the buttons of the map's bar wrap into two rows, so every control is inside its card down to 667 x 375 (the opt-in browser check measures nine sizes).

**The check.** The check of the page is the core's `checkMap` on the bytes as they are: after a change the side panel's line is run again when the hand has rested for 0.6 seconds, and the Check button runs it at once and shows the card. Download hands over a map that has not been changed as it came, and a map that was drawn on as the core writes it (`rewrite`), so it stays a valid file; the page still has no way to write over a file.

## Tests

`tests/scripts/test_web_mapmaker.py` (quick tier) runs `tests/scripts/web_mapmaker_check.js` (the reader on all 540 maps of the library, the view, the sizes, the card, the colors; broken copies of the scripts must fail it) and pins the page's wiring. `tests/scripts/web_mapmaker_edit_check.js` runs the drawing (the brush and the line, strokes in version 8 and 9, fill, undo and redo byte for byte, the bounded history, the dictionary, the palette against the game's list of names, the tools on a fake page with their keys, and hills, ants and food in version 8 and 9: where each goes, moving, the eraser, one step of the history, the bounds, a dictionary that is too short); about 80 broken copies of the scripts must fail it. `tests/scripts/web_mapmaker_objects_check.js` holds the bigger objects and the solid bit to the 540 maps of the library: the table of solid tiles to the game's flags, the list of 29 to a measure of the library made again (the tiles, their names, their footprints), each of the 29 put in a free place on every map and taken away again (the cells, anchors, flags and solid bits as the library's own objects have them; one tap on any cell takes it whole; undo and redo are byte for byte; the layers are the level they were), the same on the maps converted to version 9, what is in the way, the edge of the map, a version 9 map wider than 256, a dictionary that is too short; Python counts the library's objects again with struct, and about 20 broken copies must fail it. `tests/scripts/web_mapmaker_blocks_check.js` holds the lists to the 540 maps of the library (every list is read where it is and written back as the same bytes, a change and its undo give the bytes back, a hill taken away and put back is the same cells, nothing but what is named changes), and Python reads the same lists again with struct. `tests/scripts/web_mapmaker_dialog_check.js` runs the dialogs on a small fake of the DOM (focus, Escape, Tab, New map; broken copies must fail it). The canvas and the page's start need a real browser: the opt-in check covers them. `tests/scripts/web_mapmaker_core_check.js` holds the page's reading, and the maps it has drawn on, to the real module (the core reads, checks and writes an edited map as the same level, the objects keep their anchors through a conversion in both directions, undo gives back the cells of all 540 library maps, the checker says "Blue has no hill" until the hill is there and counts the ants and the piles that were put, writes the edited file as the very same bytes, and every whole hill of the library, as a Classic and as an Extended map, taken away and put back is the same level; all 29 bigger objects on a blank map of each kind, and three on each of the 540 maps, leave the checker's verdicts as they were, are written as the very same bytes, and keep their anchors through a conversion in both directions; the web job of CI runs it from the image). The opt-in browser check is `tests/scripts/test_web_mapmaker.sh` ([`TESTING.md`](TESTING.md)).
