# The map pages

One public page for every map of the library, and an index of them: the pages that people find by the name of a map from the 1998 game. `/map/NAME` is a map's page, `/map-library` is the index (`/map-library?page=N` the later pages of it). The server's own list of maps, `GET /maps` ([`SERVER.md`](SERVER.md#the-list-of-maps)), keeps its address and its job; the two have nothing to do with each other but the library.

The pages are made when the web image is built, from the library, by `tools/map_pages.py` (Python standard library only), and are plain files that nginx serves: a page is not filled in by a script, so a search engine and a visitor with no script get all of it. One page for each map of the library today: the six maps of `Original-Ants/Maps` and the players' maps of `Community-Maps/` (one page for each different file: a file that was shared under several names is one page). The maps that players send and the maintainer approves ([`MAP_SUBMISSIONS.md`](MAP_SUBMISSIONS.md)) live on the game server and are not in the library that the build reads, so they have no page yet.

## What a page holds

The look is the one of the match pages (`web/matches.css`, the bar at the top: [`SITE_NAV.md`](SITE_NAV.md)) with the rules of `web/map_pages.css`; the page's skeleton is `web/map_pages/page.html` (the template of both kinds of page; the folder is the tool's, the image does not copy it). In the bar the page has **Maps** (`/map-library`) between Matches and Map maker; the other pages' bars do not have it yet.

- **The picture** (300 by 300, the one that the Map Maker's list and the front page use: `/front/preview_<name>.png` for an original, `/maps/previews/<name>.webp` for a player's map), the name (the file name without `.lvl`, as it is: the name is the player's), a tag **Original** for the six, and a line with the size and the players.
- **The map's own line** (the 27 characters of the file's header, shown as the game's setup screen shows it) as a quote. The sign that the old editors put first (`!`, `*`, `^`) and the padding are not part of it; a line that the header cut ends in three dots as it does in the game. A map with no line has no quote.
- **Play it** (`/?hostmap=<file name>`: the front page opens a room of its own on this map, and its leader may share the link or add bots, as in any room; a page that holds a room already makes none and changes none, [`HOME_SCREEN.md`](HOME_SCREEN.md#addresses)) and **Open in Map maker** (`/mapmaker?mapfile=<file name>`: the Map Maker opens the map as a copy under a free name, after the question about unsaved drawing; [`MAP_EDITOR.md`](MAP_EDITOR.md)). A map whose file name the game page and the Map Maker could not fetch has neither button.
- **About this map**: a few sentences written from the facts, which is the text that a search engine reads: what the map is, its size, the length of a game, whether it has food and power-ups (so which game types suit it), a link to the matches played on it (`/matches?q=<name>`), a note when the file was repaired for the library (the sentence of `maps.json`), and the other names that the same file was shared under.
- **Facts**: kind, size, players (four anthills on every map of the library), game length, food (the piles of block 2 of the file), power-ups (the cells of layer 2 with a tile of 62 to 66), starting ants (the start markers of the four colors, "N each" when they are equal), the maker (below), the file (name and size), the other names. The counts are read from the file by the tool, by the same rules as the server's ([`MAP_FORMAT.md`](MAP_FORMAT.md), `src/ants_server/online_limits.cpp`); a count that the file does not give is not shown.
- **Game types it suits**: Highest score for a map with food, 187 for every map ([`GAMEPLAY.md`](GAMEPLAY.md#187-a-game-type-of-the-remake)).
- **Maps like this one**: four, those that share a word of the name (most words first), then those of the same size and kind, spread by a fixed number so that the pages that share a size do not all name the same four.

**The maker** is shown only when the map's line clearly names one: the text ends in the name after "by", "made by", "created by", "designed by" or "HQS by" at its start, "made by" anywhere, "by:" or a "by" after an exclamation mark; the name is one word (up to three joined by "and", "&" or a comma) of at most 24 characters with a letter in it; a line that ends in three dots right after a letter or a sign (the header's cut, or a player's own ending) names nobody, because the name may be cut; "improved by", "surrounded by" and every other "by" name nobody. With no maker the page has no "Made by" anywhere: the line under the name says it is a player's map of the 1998 game.

**Played here** (the matches that were played on a map) is read when the page opens: `web/map_plays.js` asks the site's list of maps (`GET /maps`, the same door as the index's "Most played") for the number of this map's file, shows the fact and the sentence "It has been played N times on this site: see its matches." ("Not yet" and "be the first" for 0), and puts the number in as text. With no answer of the right shape (no list, no entry, a number that is not a whole number) nothing is shown and the page keeps the sentence that it came with, a plain link to the matches. The server counts a map's plays by its file name and hash; a server with no database counts none. The index asks the same list when "Most played" is chosen.

## The addresses

`NAME` is the file name's lower case letters and digits, every other run of characters one hyphen (`!!!!!!aLkAtRaZ!!!!!!` is `alkatraz`). Two different maps with one word: an original keeps it, then the name that sorts first; the others get a short tag of their own file name after it (`fire-f888`), which never depends on the other maps. A name that is only signs becomes `map-` and six digits of a hash, a name of more than 60 characters is cut and gets four. **An address that a search engine has listed never changes**: the ledger `tools/map_page_slugs.json` holds every address and the file of its map, and the tool reads it first: a map in it keeps its address whatever has been added to the library, an address of a map that is gone stays taken, and a new map gets a free one. A test fails when a new map is not in the ledger yet, so that its address is saved before it can move (`python3 tools/map_pages.py --slugs > tools/map_page_slugs.json`).

The copies of one file under several names are one page, of the original, else of the spelling that most of the names share (looking at letters and digits only), then a name that starts with a letter or digit, then the name that sorts first. The other names redirect to it with a 301 (`/map/alleyants` to `/map/alley-ants`), the query kept; a name that is already another map's address is not redirected. nginx compares the names of this list without regard to case, so `/map/AlleyAnts` goes to the page too; a name that is no other name of a map (`/map/Treasure`) is the 404.

nginx (`docker/nginx.conf`): `/map-library` is a location of its own and `/map/NAME` is one regular expression (after the doors that have one: the first regular expression of the file stays the hub's picture door); both rewrite internally to the file that the build made (`/map_pages/map/NAME.html`, `/map_pages/library/N.html`), so the answer has the headers of a page, the revalidation header and the ETag; the query goes with it. The files are no addresses: their `.html` addresses and a slash after a page are a 301 to the clean address (one `map`, `$ants_map_redirect`, which also holds the other names). An address that names no page is the site's 404: another name, other letters, two hyphens in a row, a slash and more, a page number that is not a plain number (a page number is digits only: it is put into a file name) or is past the last page. The other names of the maps are lines of that map, read from `/etc/nginx/ants-map-pages/*.map` (a glob: a server with none, a test of the file, starts and moves no name).

## The index

`/map-library` is page 1 of the index, 48 maps to a page, the six originals first (in the order of the page) and then the players' maps by name (the signs in front of a name do not count), each card a plain link to the map's page; `/map-library?page=N` is the later pages, with the pager as plain links. `web/map_library.js` (loaded with the list `map_library_data.js`, which the build writes beside the pages: the maps, and the tops of the sizes and of the game lengths, so that the numbers have one home, `tools/map_pages.py`) adds the search ("a name or its words"), All / Original / Made by players, Size (small up to 31 x 31, medium up to 60 x 60, large above), Game length (up to 10, 11 to 15, over 15 minutes), Players (only when the library has more than one kind of map) and Order (originals first, name, most played). While one of them is used the script draws the matching maps itself, 48 to a page, and with all of them cleared it puts the page back. A name or a line is put in as text, never as markup.

**Random map** is a button beside the page's title (under its line on a phone) that opens the page of a map of the whole library, a new one each time it is used: the link is made again by `web/map_library.js` from the full list when the page loads and at every use, so it can also be opened in another tab. The page has no such link without script (it is hidden until the list is there), and a list with no map shows none. The room's own list of maps has the same row: [PLAY_MATCH_SETUP.md](PLAY_MATCH_SETUP.md#choosing-a-map).

## What the head of a page says

The title is `<name> (<original map | map by NAME | player map>, W x H) — Ants (1998)` and at most 70 characters (a long name is cut); the description is the facts, the map's own line and an invitation, at most 175; the canonical link is the page's own address (page N of the index names itself, page 1 is `/map-library`); the share card says the same with the map's picture (an absolute address); a map page has a `BreadcrumbList` (Home, Maps, the map). A sitemap of their own, `/sitemap-library.xml`, lists `/map-library` and every map page (`tools/seo_files.py --pages`; `robots.txt` names it beside `sitemap.xml`, and those two files are the same with and without it, because the image check of a Dockerfile change tells a changed file from an added one; [`BUILD_AND_RUN.md`](BUILD_AND_RUN.md#search-engines-and-share-cards)); robots.txt opens `/maps/previews/` (the pictures) and keeps the rest of `/maps/` shut.

## How it is made

- `tools/map_pages.py ORIGIN OUT_DIR [--version V --build-id ID --build-date TEXT]` reads the library (never writes it: `tools/library_guard.py`) and writes `html/map_pages/…`, `html/map_library_data.js`, `nginx/moved.map` and `addresses.txt` below `OUT_DIR`; `--slugs` prints the addresses. Everything that a player wrote is escaped for the place it goes into (HTML, an attribute, JSON in a script), and the template's slots are filled in one pass, so that a name that looks like one is text.
- The image (`Dockerfile`): one layer of the builder stage after the compile layers runs the tool with the stamps of the other pages and the site's address (`web/SITE_ORIGIN`), and the layer that makes `robots.txt` and `sitemap.xml` takes the addresses from it (`tools/seo_files.py --pages`); the last stage copies the pages into the web root, `moved.map` into `/etc/nginx/ants-map-pages/`, and `web/map_pages.css` and `web/map_library.js`. `build_web.sh` does the same for a local web build.
- Pictures: the ones that exist (300 by 300). Pictures made on the server, and a larger render, come later.

## Tests

`tests/scripts/test_map_pages.py` (the tool: addresses and their ledger, the other names, the maker, escaping, the head of every page, the links that a page makes, the index, the sitemap, the tool's refusals; `tests/data/map_pages_mutants.json` holds a mutant for each product rule: escaping, stable addresses, the maker rule, the sitemap, valid file names, the address of Play it, a Random map link that is hidden without script and a list that holds only addresses of pages), `tests/scripts/test_web_map_library.py` (the index's script, with its Random map link, and the play count run on a fake of the DOM, the Map Maker's address, budgets, the image's wiring; `tests/data/map_library_mutants.json`), `tests/scripts/web_rematch_check.js` (the room that `/?hostmap=` opens; `tests/data/rematch_mutants.json`), `tests/scripts/test_nginx_map_pages.py` (the routes, run by the real nginx of the image where docker works; `tests/data/nginx_map_pages_mutants.json`); `tests/scripts/web_routes_check.py` also asks the built image for the pages (the CI), and `tests/scripts/test_web_seo.py` keeps the crawler rules. The tool is run on the real library by all of them.
