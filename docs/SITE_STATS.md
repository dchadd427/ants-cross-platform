# The site statistics (`GET /stats` and `POST /stats/local`)

The WebSocket port of the game server answers `GET /stats` and `POST /stats/local` besides `GET /busy` ([`SERVER.md`](SERVER.md#busy-and-stats)). Neither needs a secret, and the answers hold numbers only. This page was a part of `SERVER.md` and is moved here whole, so that `SERVER.md` stays under its size limit.

**The site statistics, `GET /stats` and `POST /stats/local` (on the WebSocket port, `site_stats.hpp`)**: the front page shows how many games were played. Two counters, each for the **last 24 hours** (24 buckets of an hour on the server's clock: the hour that runs and the 23 before it) and **in all**, and `since`, the UTC day they count from. **`online`** is a match that ran **at least 600 ticks (30 seconds of play)** and ended, in any room (demo rooms too: every web match is one), counted once when `RoomManager::take_ended` tells its end (`SiteStats::kMinTicks`): a match that the owner closed, a desync or the room's time limit ended counts once it has run that long; a shorter one counts nothing, nor does a room that never began (nobody came, closed while it waited or during the "Get ready" dialog), so a start-and-quit loop cannot pad the number; a match that a stop of the server cuts off is not told as ended and is not counted, and one that the server brings back from a restart record is counted when it ends (its ticks go on from the record's). **`local`** is a single-player game that a browser reports: **the game runs in the tab, so the server cannot see it, and a script can post as well; it is what browsers say, a figure for the page and no proof.** `GET /stats` is answered as `/busy` is (the same door rules; `Cache-Control: no-store`) with `{"now":{"matches":N,"players":M},"online":{"day":D,"total":T},"local":{"day":d,"total":t},"since":"YYYY-MM-DD"}`: `now` is `/busy`'s answer, the rest numbers and one date (it is not the control interface's `GET /stats`, which is behind the secret and never routed). `POST /stats/local` takes **no body and no query** (`WsServerOptions::post_path` and `post_action`: exactly that path, no `Upgrade`, one `Host`, `Content-Length` absent or 0, no `Transfer-Encoding`; another path or method is 405 and `Allow:` says what the path takes, a malformed request 400; the parser stays pure and only says `posted`, the listener runs the action once), counts one game and answers **204**; **at most 120 reports count in any 60 seconds**, the others get the same 204 and are not counted (the cap cannot be seen), and the server keeps nothing of a request but the count (the web server's own access log is what it is for every request). The counters live in **the database** ("The database" in [`SERVER.md`](SERVER.md#the-database): the tables `site_stats` and `site_stats_hours`, schema version 4), written whole in one transaction **at most every 10 s while something changed** and at a clean stop (a write that fails is rolled back and leaves the last numbers whole, the log says so once), read at start; a crash loses the last 10 s at most. **An older server kept them in `site-stats.json` of `--results-dir`** (`{"format":1,"since":...,"online":{"total":T,"hours":[[hour number,count],...]},"local":{...}}`): the first start with the tables reads that file into them at once (every number and the date) and leaves it as it was; later starts read the database and never the file again; a file that is no usable file (not JSON, a counter that is no number, buckets that hold more than the total, a date that is no day) is put aside as `site-stats.json.broken-<seconds>`, the counters start at 0 and a log line says so. With `--no-db` the counters are kept in that file as before (written whole to a temporary file, flushed to the disk and renamed); without a results folder they live in memory. `docker/nginx.conf` forwards both as exact locations like `/busy`, with **nothing of the visitor's headers** passed on (the server is sent `Host`, `Connection` and, for the POST, `Content-Length: 0`: a cookie never reaches it, however big): `/stats` GET only (405, a query 404), twenty a second per address with a burst of 100, **answered from a cache of 5 seconds** (one entry for everybody, so the game server is asked about once in 5 seconds however many people look; an old answer is served while the new one is fetched and when the server does not answer; the server's `no-store` still reaches the browser); `/stats/local` POST only (405, a query 404), a request that the browser says is cross-site (`Sec-Fetch-Site: cross-site`) is 403 before it counts against the limit (the game page's own report is same-origin), sixty a minute per address with a burst of 20 and **never a body passed on** (the server is given an empty POST; a body over 1 KiB is 413); 503 beyond the limits; a 3-second connect timeout and 5-second read and send timeouts. The limits are sized to hold for the whole site, because behind a reverse proxy that ends TLS every visitor may have the proxy's address (the server's own cap of 120 a minute is the bound that matters). **The web game reports its own games**: `Application::set_on_local_match_started` is told at the first tick of a game on this computer (once for each match, never in a match of the network; only the web build sets it, to a call of the page's `antsReportLocalGame()` in `web/shell.html`: one `fetch('/stats/local', {method: 'POST', keepalive: true})`, no retry, every failure ignored); a native game reports nothing. Tests: `test_ws` W1.25 (the door), `test_server` S3.140 - S3.149 (the counting, the window, the cap, the file, the answer, a real manager and a real listener), `test_site_stats_db` (the tables, the import of the old file, a write that fails), `tests/scripts/test_ants_server.sh` (the real program, its rooms part), `tests/scripts/test_nginx_stats.py` (the blocks, the limits and the cache, run in front of a stand-in server, and in front of the real program), `test_app_integration` 7.6h and `test_network_app` N5.90 (the hook), `tests/scripts/web_report_check.js` and `test_web_report.py` (the page's function).
