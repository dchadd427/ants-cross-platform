# Replays

A match of this game is its starting data (the map, the seed, who plays, the teams) plus the orders that the players gave, turn by turn: the engine is deterministic, so the same data and the same orders give the same match on every machine. A replay file holds exactly that, and a few checks that say whether a machine plays it out the same way. `replay_tool` reads a file, plays the match again with no window, and lists every order with its time, its place and the types of the ants that got it.

**Built:** recording in the desktop game; the file; `replay_tool`; the game server keeps the matches that its rooms play (the browser's matches too) for 30 days and lists and gives them out, and lists the ones that run now and gives out each as far as it has gone ("On the game server" below); the site's list of them and the player in the game page ("Watching a replay"); computer players' matches saved by `bot_arena --save-replays`, which show in the same list ("Matches of computer players"). **Not built yet:** [`replays/DESIGN.md`](replays/DESIGN.md) is the design for the rest (a seat's point of view, a table of statistics); this page says what exists.

## Recording a match

Every match that the desktop game plays is recorded while it is played: a game on your computer (alone or against computer players) and a match of a room, as its host or as a guest. Nothing is switched on, and recording changes nothing in the game: it only watches the orders that the engine is given and the ticks that it runs. The browser game records nothing, and it has no button for a file: a page has nowhere to keep one, and a file could not be watched without the game anyway. What a browser plays in a room is recorded by the game server, which keeps it ("On the game server").

- **The file** is named after the map and the date and time of your computer, for example `ants-TREASURE-20261006-143209.antsrep`, and is written when the match is over, into the folder `replays` beside the settings file: `~/Library/Application Support/Ants/Ants/replays/` on macOS, `~/.local/share/Ants/Ants/replays/` on Linux, `%APPDATA%\Ants\Ants\replays\` on Windows (with `--settings FILE`, the folder of that file; [`CONTROLS.md`](CONTROLS.md#settings)). The console says `Replay saved: <path>`. A file that is there is never replaced: a match that ends in the same second as another gets `-2` (then `-3`, and so on). The game never deletes anything from this folder, so it grows with every match that you play: clear it out when you like. A headless run without a settings file keeps nothing on disk.
- **A match that you leave** before it is over is kept as well, when something happened in it: you gave an order (the quit is one) or a minute went by. What the computer players or the other players did does not count, so a match that you walk away from in the first minute leaves nothing, however busy the others were. The file says that the match was not over. When a recording cannot be a file (a turn of a network match never arrived, or the file would pass 1 MiB), nothing is kept and the console says why.
- **Names:** in a game on your computer the file holds the names that were typed or given (a computer player's "Bot (Medium)", `--name`, `--team-name`, the name typed in the start menu); the name that the program makes of your system user stays out, because a file may be sent to someone. In a match of a room the names are the ones that the room showed everybody (the game server's own files leave out the words "Player" and "Player 1" to "Player 4", below). A name in the file is plain ASCII, the letters from the space to the tilde: every byte of anything else becomes a `?` (a letter with an accent is two bytes and gives `??`), and a file whose texts hold anything else is refused when it is read.

To show someone a match, send the file. They need a build with the same `sim_rules` ("Watching a replay") and the same map; `replay_tool info FILE` says which.

## On the game server

The game server (`ants_server`, [`SERVER.md`](SERVER.md#replays) has the options and the numbers) records every match that is played in one of its rooms, the games of the web pages included, and keeps the file when the match is over. Nothing is switched on by a player and nothing changes in the match: the referee's own runner is watched, as in the desktop game.

- **What is kept.** A match that ran at least 30 seconds, however it ended: the rules ended it, a player quit, the owner closed the room, its time limit, a desync. A shorter match is not kept. Not kept either: a match that the server brought back from its restart record after a restart (the recorder did not see the part before the restart), a room that was made with `"record": false`, and a solo game in a browser tab (it is not played on the server). The games of the front page (the demo rooms) are kept when the server is started with `--replay-demo`, which the stack file does. The room's own status (`GET /rooms/<code>`) says whether its match was kept and, if not, why.
- **How long.** The files are deleted 30 days after the match ended, and there is a limit on all of them together, the oldest first. By default the folder is on the server's results volume, which also holds the control secret and the restart records, so a disk that is nearly full, or a flood of matches, stops new files and never the server.
- **Names.** A person's seat keeps the name that the room showed everybody, which is the name that the player typed. It is plain ASCII (the letters from the space to the tilde; every byte of anything else becomes a `?`, so a letter with an accent, which is two bytes, gives `??`), at most 32 characters, with the blanks at both ends cut, and the readers show it after the colour: "Green (Ann)". A seat with no name of its own shows its colour alone ("Green"): the player typed nothing, or only the words that the game itself uses for a player without a name, "Player" and "Player 1" to "Player 4" (a name that only starts like them, such as "Players" or "Player 5", is a name and is kept). A computer player's seat has its display name: "Bot (Easy)", "Bot (Medium)", "Bot (Hard)". The front page picks a plain word (such as "Maple") for a visitor who typed no name, and that word is kept like a typed name. **These names are public wherever the public door is on** (next point): the stack file turns it on, so on the public site everybody can read the names of the players of the kept matches, in the list (the newest 200 files) and in the files, and a page that shows them must show them as text. No address, room code, key or chat is in a file, and the file's own name is only the map and the time the match ended: `ants-TREASURE-20261008-143209Z.antsrep` (UTC, with a `-2` when two matches of a map end in one second). The name screens of the pages tell players so ([`SERVER.md`](SERVER.md#replays)).
- **Who can get them.** The server's owner, with the control secret: `GET /replays` lists them, `GET /replays/<file>` gives a file and `DELETE /replays/<file>` deletes one ([`SERVER.md`](SERVER.md#the-control-interface)). **And everybody, on the public site: the list and the files are public.** `docker-compose.stack.yml` opens the server's read-only replay door (`--replay-port`; the program's own default is off) and `docker/nginx.conf` passes `GET /replays` and `GET /replays/<file>` of the site to it: a plain GET and nothing else, with limits and a short cache for the list ([`SERVER.md`](SERVER.md#replays)), and a plain `404` with a JSON body when the server has no such door. The list gives the newest files that this build can read, and for each the map, the players ("Green (Ann)" for a player with a name, "Green" for one without, "Red (Bot (Medium))" for a computer player), the length, whether the rules ended the match, the game version, the protocol number (`rules`) and the simulation rules number (`sim_rules`, and the list's own `sim_rules` is the serving build's). A visitor can download a file and play it with `replay_tool`, or watch it on the site (["Watching a replay"](#watching-a-replay)).
- **Live.** The matches that run now are public too, on the same terms as the kept ones: `GET /live` lists them (the matches that ran 30 seconds or more, the newest 50, with the same players strings as the replay list) and `GET /live/<id>` gives one as a **snapshot**, which is the match's replay file as it is at that moment. A snapshot is an incomplete file (it has no `ENDS` chunk) with one more chunk, `live`, that says how many turns the match has run ("The file"), so a page plays it with the code that plays a replay, up to the turn it has and no further; to follow the match it fetches the snapshot again and plays on. **There is no delay, on purpose:** the picture is behind the match only by the time that it takes to reach the page, because this game has no hidden information online (the site offers no Fog of War), so a delay would hide nothing. The server makes a snapshot at most once a second for a match, however many watch it (and the site's cache keeps one for 2 seconds), and when a match ends the id answers with the name of its replay file for 15 minutes, so a page that watched finds the replay. A match played with Fog of War is not shown while it runs (it would show what the fog hides). The ids hold the map and the second the match began and nothing of the room. The routes, the numbers and the limits are in [`SERVER.md`](SERVER.md#replays).
- **A file from the server** is a file like any other of this page: `replay_tool info FILE` says what it holds, and a build plays it only when its `sim_rules` is the same as the build that recorded it (a match recorded before an update that changes how matches play out stays in the list, under "Earlier versions" on the site's page, until it is 30 days old).

## Watching a replay

The pages are the site's own: one **Watch matches** link in the footer of the front page, the game page and the list, and a **Watch matches** button in the header of the front page and of the game page (a new tab on the game page, so that a match being played there goes on; not shown while a replay is watched, whose header has "All matches"), the **list** at `/watch.html` and the **player**, which is the game page opened as `/play.html?replay=<file>` (or `?live=<id>` for a match that is being played, below). Nothing is switched on and no account is needed.

- **The list** (`web/watch.html`) reads the server's public `GET /replays` and shows the newest matches first: the map's picture and name, the day and time in the visitor's own time zone ("Today, 7:32 AM"), the length, and one chip for each player in the colour of the seat, with the name that the player typed (the colour word when nothing was typed, "Bot (Medium)" for a computer player). Ten matches show at first and "Show more" adds ten. **Watch** opens the player, **Download** gives the file. A match that was left before the rules ended it says **Cut short**: it plays as far as it goes. The words for a server that keeps no replays, a list that is empty and a list that cannot be loaded are on the page. Every name is put in as text and never as markup (`tests/scripts/test_web_replay.py` pins it).
- **The player** is the game itself in a replay mode (`--replay FILE`; the web page fetches `/replays/<file>`, writes it into the game's file system and starts the game with it). The game plays the match from the file on its own engine, shows the whole map (no Fog of War), and throws away every order of the HUD, so a visitor cannot change the match. Above the picture: the map, the time, the players, and the buttons **All matches**, **Copy link**, **Download** and **Fullscreen** (on a phone: **All matches**, **Full** and **More**). Under it: play and pause (the space bar too), the timeline (click or drag to jump to a moment; the arrow keys jump 10 seconds, Home and End go to the ends), the time and the length, and the speed ½×, 1×, 2×, 4× and 8×. The tag **REPLAY 1×** (or **Paused**, or the live words below) sits just above the bar, never over the picture (the bar's top margin makes the room: about 25 pixels, which a short window takes from the picture's height). A jump rebuilds the match from the start on the same engine (the game does it in slices, and a veil with a bar says "Jumping to 3:20…" when it takes a moment). At the end the game's own results screen shows and the play button becomes **Watch again**. In fullscreen the bar lies over the bottom of the picture, with the tag above its left end and a small tab on its top edge, and goes away by itself three seconds after the last touch of it (or the last move of the mouse) while the match plays (it stays while the match is paused); a swipe down on it (not on the timeline, which keeps its own drag) or a tap on the tab hides it at once. **A finger on the picture never calls the bar**, so a tap or a drag of the map leaves the picture clear; a tap, or a swipe up, along the bottom edge calls it (a tap calls it in its click, so that it does not press the button that the bar then has under the finger; a strip about 56 pixels high with nothing drawn on it, there only while the bar is away and the last touch was a finger, so that a mouse keeps the game's edge; on a phone with gesture navigation the very bottom belongs to the system, and a touch that starts a little above it works). The first time in a visit that the bar goes away after a finger was used, a note says for 3 seconds how to bring it back. A mouse, a pen and the keys call it as ever.
- **The page and the game talk through two exported functions** (`ants_replay_get(what)` and `ants_replay_do(what, value)`, the enums are in [`include/ants_app/replay_view.hpp`](../include/ants_app/replay_view.hpp)) and two calls of the game to the page (`window.antsReplayReport(info)`, what the file is or why it cannot be shown, and `window.antsReplayLeave()`). The state, the turn and the speed are the game's; the page only draws the bar.
- **A file that cannot be shown says why** on a card over the picture: recorded by an older version (it names both, and offers the file), recorded by a newer one ("Load the page again"), gone ("Matches are kept for 30 days"), or one that cannot be played (the map is missing, the file is damaged, the match does not play out the same here). A name in the address that is not the shape of the server's own file names is never fetched.
- **The same game in the same browser as ever:** pointer lock is off in a replay, so the bar is clickable, and leaving the page never asks "Leave the game?".
- **A match that is being played** is watched as a replay whose file is still growing: no new connection and no new protocol, only the public door ([`SERVER.md`](SERVER.md#replays)). The list's **Live now** box (above "Earlier matches") reads `GET /live` every 10 seconds while the page is in front and shows each match with a red **Live** mark and its length so far; **Watch live** opens `/play.html?live=<id>`, and the **Watch matches** link of the front page goes to the list too. The player gets `GET /live/<id>` (the recording so far), starts the game with `--replay --replay-live`, and every 4 seconds fetches the file again, writes it over the game's copy and calls `ants_replay_do(Extend)`; the game takes it when it is the same match with more turns and plays only up to 40 turns short of its end, so the picture is about 10 seconds behind the players. The tag above the bar says **LIVE about 10 s behind**, or how far behind a paused or moved playhead is (**Paused · 0:59 behind**), **Jump to live** goes to the present, and Download waits until the file is whole. A feed that fails says "The live feed stopped. Trying again…" and goes on trying. When the match ends the door answers 404 with the name of the kept file: the page fetches it, Extends once more and goes on as a replay of the whole match (its address becomes `?replay=<file>`, "The match is over. It is now in the list as a replay."); a match that was not kept ends where the game holds it (`LiveOver`, "The match is over."). A link to a match that has ended has a card with **Watch the replay**, and a link to a match that is not live (or an id that is not the shape of the server's, which is never fetched) says "That match isn’t live". What the door says is shown as text and never as markup. `tests/scripts/test_web_live.sh` (opt-in) checks these pages, and the tag and the fullscreen bar of the player (`--only bar`), in a real browser against a fake door and a stand-in for the game.

**Which files play: `sim_rules`.** A recording plays only on a build that computes the match the same way. That used to be the network protocol's number, which moves whenever the wire format does (v0.12.0 made it 16 for lobby rooms without touching the simulation), so every protocol bump would have stranded the files before it. The head now has its own field, `sim_rules` (a small number, `replay::kSimRules`, 1 now), which changes **only** when a match plays out differently (a golden hash moves: the engine, the map reader, the original's tables). A file plays when its number equals the build's. A file made before the field has none: a table in `replay.cpp` maps the protocol numbers that are known to play out the same way (15 and 16 → 1) and any other number is unknown (0), which no build claims. The server's list says it for every file (`sim_rules`, and the list's own top-level `sim_rules` is the number of the build that serves it), and the page shows the files of another number in a box "Earlier versions", with Download and no Watch. When a change makes matches play out differently, raise `kSimRules` in the same change: `test_replay` RP7.1 - RP7.3 play a reference match and fail when its final hash moves and the number does not (and when the number moves for no reason), so a stranded file cannot slip in. Raising it adds the old protocol numbers to nothing: the old files stay in the list under "Earlier versions" until they are 30 days old.

## Matches of computer players

`bot_arena --save-replays DIR` (the tool of [`BOTS.md`](BOTS.md)) keeps every match that it plays as a replay of the server's kind in the folder `DIR`, through the server's own store (`ReplayStore`: the names `ants-<MAP>-<date>-<time>Z.antsrep`, tmp file and rename, the 30 days and 100 MiB limits). The head says venue "bot arena", no Fog of War and the display names of the bots ("Bot (Medium)", "Bot (Hard)"), so the list shows them as "Green (Bot (Hard))" like the bots of a room, and the player plays them back to the hash of the arena's own match (the tool's self-test checks this). A match under 30 seconds is not saved, as on the server. **How they reach the site's list:** point `DIR` at the server's replays folder (`replays` in its results volume). The arena's own store deletes nothing (its limits are the largest ones: 3650 days, 4 GiB), so pointing it at the server's folder does not cost the server a file at the stack's limits (the one exception would be a server set to 4096 MiB with its folder full to the brim). The server looks at that folder again every 30 seconds when its change time moved (`ReplayStore::rescan`): a file that was put there is listed (one that changed in the last two seconds waits for the next look, so a copy that is still growing is not taken for a damaged file; a file that could not be read or changed its size is read again), a file that was taken away is forgotten without deleting anything, and the server's own limits then apply to the files from outside too: a file older than 30 days that is copied in is deleted again at once. A store that opens the folder deletes the half-written `.tmp` files of a crash, but not one that changed in the last two seconds (`settle_s`): that is the write of the other program, which renames it in a moment, so the server and the arena can open the folder at any time. Two writers of the same name in the same second could still replace each other's file (a rename replaces on Linux), and never run two arenas on one folder at the same time. **On the site's host:** the stack file runs the arena as its own service, `ants-arena` (`docker-compose.stack.yml`, the stage `arena` of `Dockerfile.server`, the loop `docker/arena_loop.sh`): every `ANTS_ARENA_EVERY_MIN` minutes (60 by default) it plays one match of two to four standard bots at Medium or Hard level on one of the six maps and keeps it in the server's folder (about a second of one processor; 4 to 8 KB a file; no network, no ports; the server's `ANTS_REPLAY_DAYS` and `ANTS_REPLAY_MAX_MB` purge these files with the others). The list shows the newest 200 files of all kinds together, so the arena's 24 matches a day take 168 of them in a week and the list reaches back a week only while the players make about 4 matches a day or fewer (at 10 a day, about 6 days); a longer interval keeps older matches of players on the list, a shorter one pushes them off sooner. The log of the service says the map, the seats and the seed of every match, so `bot_arena` plays it again bit for bit. To switch the arena off, delete the service from your copy of the stack file.

The game server plays matches of computer players of its own too (`--bot-match-every-min`, [`SERVER.md`](SERVER.md#matches-of-computer-players)): a room with no person in it, free for all or in teams (the head of the file holds them, as for any match), at the normal speed, recorded and listed like any room's match, and shown in the list of the matches that are being played while it goes on. Those matches are what the "Live now" box of the list shows when nobody else is playing, and the hourly match of the stack's `ants-arena` service does not exist any more unless that service is asked for.

## The file

A `.antsrep` file is a row of chunks, like a PNG: a reader skips a chunk that it does not know (unless its first letter is upper case: then the file is refused), every chunk has a checksum, and a file that stopped in the middle still plays up to its last whole chunk. The numbers are little endian. [`include/ants_replay/replay.hpp`](../include/ants_replay/replay.hpp) has the exact layout; in words:

| Chunk | Holds |
|---|---|
| `HEAD` | the format number; the protocol number (information); the simulation rules number `sim_rules` (what a build plays a file on, "Watching a replay"); the game's version and build; "local game" or "network game"; the map's file name and its hash; the seed; the seats that play; Fog of War; the names; the teams that the match started with; the seat of the machine that wrote the file |
| `CMDS` | the orders in the order in which the engine was given them, each with its turn; one chunk for every 30 seconds of game time or 4,096 orders |
| `hash` | the low half of the engine's state hash after every 100th turn (every 5 seconds of play) |
| `ENDS` | the number of turns, whether the rules ended the match, and the state hash at the end. A file without it is incomplete: a copy that was cut short (a download that stopped, a file that was truncated), because the game writes a file whole, when the match is over or left, or a snapshot of a match that still runs (`live`, below) |
| `live` | only in a snapshot of a match that still runs ("On the game server"): the number of turns the match had run when the snapshot was made, which can be more than the last order and the last hash say. It is optional and its tag is lower case, so a reader that does not know it skips it. A reader that does takes the file's length from the largest of its last order, its last hash and this number, and refuses a file that has two of them, one of the wrong length, one with fewer turns than its last order or hash, or one together with an `ENDS` chunk |

An order is the network's own wire form (the one a room sends, [`NETWORK_PORT.md`](NETWORK_PORT.md)): its type, who gave it, the tile, the ants that it names by number. **Turn t** is the t-th tick of the engine: the orders of turn t are given first, in the order they stand, and then the tick runs (a turn is 50 ms). Orders at the last turn's number come after the last tick: a Quit that ends the match is one.

**The rules number** that a file is played on is `sim_rules` ("Watching a replay"; `replay_tool info` shows it with the protocol number that the room spoke). A file is played only by a build with the same `sim_rules`; another build still reads its header, and the message names both numbers and the game that made the file. (Before the field, the network protocol's number stood for it, and a file without the field is read through the table of protocol numbers that are known to play out the same way.) **The map** is found by its file name in the folder of the shipped maps (`--maps-dir` names another) and must be the same file: another file under that name is refused with both hashes.

**Size:** a match of computer players is a few KB (4 KB for two and a half minutes of four of them on the smallest map), a long match of people tens of KB. A recording that would pass 1 MiB is not kept (the console says so).

## The tool

```bash
cmake --build build --target replay_tool
./build/replay_tool info    match.antsrep      # what the file says: map, seed, seats, teams, length, orders (no map needed)
./build/replay_tool verify  match.antsrep      # plays it and compares every hash in the file and the final state
./build/replay_tool orders  match.antsrep      # plays it and lists every order
./build/replay_tool orders  match.antsrep --seat 1 --type bomber     # only the orders of Red that name a bomber
./build/replay_tool orders  match.antsrep --csv > orders.csv         # a table for a spreadsheet
```

(`build\replay_tool.exe` on Windows.) `--seat N` is 0 Green, 1 Red, 2 Blue, 3 Black; `--type` is worker, bomber, fire, thief, combat or swimmer; `--maps-dir DIR` says where the maps are. The exit status is 0 when the file was read (and, for `verify` and `orders`, played to the end with every hash right), 1 when the file is refused, its map is missing or the match does not play out the same here, and 2 for a wrong command line or a file that cannot be read. A file that stops early plays as far as it goes and says so; if it holds no hash either, `verify` has nothing to compare the match with and says UNVERIFIED (exit 1) instead of OK.

`orders` prints one line for each order:

```text
TINY.LVL, seed 5: Green, Red, Blue, Black; 3000 turns (2:30.0)
  time  turn  seat   order  place    ants      from     result
0:00.6    12  Green  move   (12,12)  3 Worker  (9,8)    ok
0:00.7    14  Red    move   (18,18)  3 Worker  (21,21)  ok
...
291 orders: Green 57, Red 92, Blue 65, Black 77
```

- **time** is the game time of the order (minutes:seconds.tenths since the first tick), **turn** the turn number, **seat** the colour, with the name when the seat has one ("Red (Bot (Hard))").
- **order** is `move`, `special`, `attack`, `stop`, `hatch`, `team offer` / `accept` / `refuse` / `withdraw` / `leave`, `quit` or `dropped out`; **place** the tile of a move, special or attack, or the other side of a team order.
- **ants** are the ants that the order names, by type ("3 Bomber, 1 Worker"), read off the engine as it stood when the order was given: an order names its ants by number, and only the engine knows what an ant is. Ants that were gone, never were, or belong to another seat are counted as "not there" (the engine leaves them out). **from** is the tile where the first of those ants stood.
- **result** is what the engine said: `ok`, `ignored` (nothing for it to do, for example every ant named was gone) or `refused`.

With `--csv` the same lines come as a table (`time,turn,seat,name,order,x,y,ants,from_x,from_y,result`; the text cells are in quotes). A text that begins with `=`, `+`, `-` or `@` (a name in someone else's file could) gets a `'` in front, so that a spreadsheet shows it as text and never takes it for a formula.

A **special** order is what the ant's type does with it ([`CONTROLS.md`](CONTROLS.md#mouse-controls), [`GAMEPLAY.md`](GAMEPLAY.md#special-abilities)): a Bomber plants a bomb at the place or defuses one, a Fire ant lights a fire wall or puts out a blaze, a Swimmer digs a bridge on water or demolishes one, a Thief raids a hill. For a group of workers, combat ants or mixed ants it is a plain move. After the table the tool counts the special orders by the type of ant that got them: "special orders by ant type: Bomber 12, Swimmer 3" is how to see at once whether a player bombed with bombers and dug bridges with swimmers.
