# Replays

A match of this game is its starting data (the map, the seed, who plays, the teams) plus the orders that the players gave, turn by turn: the engine is deterministic, so the same data and the same orders give the same match on every machine. A replay file holds exactly that, and a few checks that say whether a machine plays it out the same way. `replay_tool` reads a file, plays the match again with no window, and lists every order with its time, its place and the types of the ants that got it.

**Built:** recording in the desktop game; the file; `replay_tool`; the game server keeps the matches that its rooms play (the browser's matches too) for 30 days and lists and gives them out, and lists the ones that run now and gives out each as far as it has gone ("On the game server" below); the site's pages of the match history (every match, one match with its stats and its replay, the matches that run now: "The match pages") and the player in the game page ("Watching a replay"); the stats that the replay pass keeps with every record (over time, activity, combat, ants and economy: "The stats of a replay pass"), shown on the match page as a band of highlights, "Over time" and "Activity"; computer players' matches saved by `bot_arena --save-replays`, which show in the same list ("Matches of computer players"). **Not built yet:** a seat's point of view, the match page's sections for combat and for ants and economy (their numbers are kept), and what only an event sink in the engine can tell (what caused each hit, which ant struck); this page says what exists.

## Recording a match

Every match that the desktop game plays is recorded while it is played: a game on your computer (alone or against computer players) and a match of a room, as its host or as a guest. Nothing is switched on, and recording changes nothing in the game: it only watches the orders that the engine is given and the ticks that it runs. The browser game records nothing, and it has no button for a file: a page has nowhere to keep one, and a file could not be watched without the game anyway. What a browser plays in a room is recorded by the game server, which keeps it ("On the game server").

- **The file** is named after the map and the date and time of your computer, for example `ants-TREASURE-20261006-143209.antsrep`, and is written when the match is over, into the folder `replays` beside the settings file: `~/Library/Application Support/Ants/Ants/replays/` on macOS, `~/.local/share/Ants/Ants/replays/` on Linux, `%APPDATA%\Ants\Ants\replays\` on Windows (with `--settings FILE`, the folder of that file; [`CONTROLS.md`](CONTROLS.md#settings)). The console says `Replay saved: <path>`. A file that is there is never replaced: a match that ends in the same second as another gets `-2` (then `-3`, and so on). The game never deletes anything from this folder, so it grows with every match that you play: clear it out when you like. A headless run without a settings file keeps nothing on disk.
- **A match that you leave** before it is over is kept as well, when something happened in it: you gave an order (the quit is one) or a minute went by. What the computer players or the other players did does not count, so a match that you walk away from in the first minute leaves nothing, however busy the others were. The file says that the match was not over. When a recording cannot be a file (a turn of a network match never arrived, or the file would pass 1 MiB), nothing is kept and the console says why.
- **Names:** in a game on your computer the file holds the names that were typed or given (a computer player's "Bot (Medium)", `--name`, `--team-name`, the name typed in the start menu); the name that the program makes of your system user stays out, because a file may be sent to someone. In a match of a room the names are the ones that the room showed everybody (the game server's own files leave out the words "Player" and "Player 1" to "Player 4": [`SERVER.md`](SERVER.md#replays), "Names"). A name in the file is plain ASCII, the letters from the space to the tilde: every byte of anything else becomes a `?` (a letter with an accent is two bytes and gives `??`), and a file whose texts hold anything else is refused when it is read.

To show someone a match, send the file. They need a build with the same `sim_rules` ("Watching a replay") and the same map; `replay_tool info FILE` says which.

## On the game server

The game server (`ants_server`, [`SERVER.md`](SERVER.md#replays) has the options and the numbers) records every match that is played in one of its rooms, the games of the web pages included, and keeps the file when the match is over. Nothing is switched on by a player and nothing changes in the match: the referee's own runner is watched, as in the desktop game.

- Which matches the server keeps, how long it keeps them and which names the files hold are described in [`SERVER.md`](SERVER.md#replays), "What is kept", "How long and how much" and "Names".
- **Who can get them.** The server's owner, with the control secret: `GET /replays` lists them, `GET /replays/<file>` gives a file and `DELETE /replays/<file>` deletes one ([`SERVER.md`](SERVER.md#the-control-interface)). **And everybody, on the public site: the list and the files are public.** `docker-compose.stack.yml` opens the server's read-only replay door (`--replay-port`; the program's own default is off) and `docker/nginx.conf` passes `GET /replays` and `GET /replays/<file>` of the site to it: a plain GET and nothing else, with limits and a short cache for the list ([`SERVER.md`](SERVER.md#replays)), and a plain `404` with a JSON body when the server has no such door. The list gives the newest files that this build can read, and for each the map, the players ("Green (Ann)" for a player with a name, "Green" for one without, "Red (Bot (Medium))" for a computer player), the length, whether the rules ended the match, the game version, the protocol number (`rules`) and the simulation rules number (`sim_rules`, and the list's own `sim_rules` is the serving build's). A visitor can download a file and play it with `replay_tool`, or watch it on the site (["Watching a replay"](#watching-a-replay)).
- **Live.** The matches that run now are public too, on the same terms as the kept ones: `GET /live` lists them (the matches that ran 30 seconds or more, the newest 50, with the same players strings as the replay list) and `GET /live/<id>` gives one as a **snapshot**, which is the match's replay file as it is at that moment. A snapshot is an incomplete file (it has no `ENDS` chunk) with one more chunk, `live`, that says how many turns the match has run ("The file"), so a page plays it with the code that plays a replay, up to the turn it has and no further; to follow the match it fetches the snapshot again and plays on. **There is no delay, on purpose:** the picture is behind the match only by the time that it takes to reach the page, because this game has no hidden information online (the site offers no Fog of War), so a delay would hide nothing. The server makes a snapshot at most once a second for a match, however many watch it (and the site's cache keeps one for 2 seconds), and when a match ends the id answers with the name of its replay file for 15 minutes, so a page that watched finds the replay. A match played with Fog of War is not shown while it runs (it would show what the fog hides). The ids hold the map and the second the match began and nothing of the room. The routes, the numbers and the limits are in [`SERVER.md`](SERVER.md#replays).
- **A file from the server** is a file like any other of this page: `replay_tool info FILE` says what it holds, and a build plays it only when its `sim_rules` is the same as the build that recorded it (a match recorded before an update that changes how matches play out stays in the list, under "Earlier versions" on the site's page, until it is 30 days old).

## The match history

A recording is kept for 30 days. What the match came to is kept for good: the game server keeps one record for every match it recorded, with who won, the scores or kills, who killed and lost how many ants, how many were hatched, the bombs and the fires, and the names that the players typed. The recording can be gone and the record stays; the server never deletes a record by itself (the owner can: below). Nothing is counted while a match is played and nothing changes in a match: the numbers are the engine's own, counted when the match is over by playing the recording once more.

- **How a match is counted.** A match is played again with no screen (`replay::play()`: 0.4 - 0.5 s for a match of 10 - 12 minutes, more for a longer one) and the engine's own `MatchResult` (the one that the match's results screen is built from; `replay::Outcome::result`, with `dropped_mask` for the seats that left on the way) says what each seat came to, so the numbers are the ones a player saw at the end. This is done by the *feeder* on the server's own loop, one recording at a time, in one database transaction, and only while no room runs or loads a match (and none is being restored after a restart), so a match is never slowed down by it. The pace follows the work: the gap after a recording is counted from its end and is at least 250 ms and four times the time that the recording took, so the loop is free for most of the time even while a backlog of 30 days is counted. The recordings that the replay store holds when the server starts (up to 30 days of them) are counted the same way, the newest first, and so are the matches that come later: a room's own, and the files that the bot arena puts in the folder. A recording that cannot be counted is left out, once, with one line in the log (the first ten are named, the rest are counted in the summary): a map that is not on the server (or another file of the same name), a recording that does not play out the same here. A recording of other simulation rules (`sim_rules`, ["Watching a replay"](#watching-a-replay)) cannot be played by this build and is not counted; the summary line says how many.
- **What is kept, and where.** In the server's SQLite database ([`SERVER.md`](SERVER.md#the-database)), three tables made by schema version 2 (and `map_plays`, the play count of each map, made by version 3 and written in the same transaction: [`SERVER.md`](SERVER.md#the-database)): `history_matches` (one row for each match; a column and an index for everything the list filters or sorts by), `history_seats` (one row for each seat) and `history_markers` (the owner's deletes, below). The id is the recording's file name without `.antsrep`: `ants-TREASURE-20261008-143209Z`. `--no-history` keeps none and `--no-db` leaves it nothing to live in ([`SERVER.md`](SERVER.md#replays)). A year of 40 matches a day is 15,000 rows of about 1 KiB. `history_matches.details` (nullable JSON text, 1 to 3.5 KB) holds the stats of the replay pass ("The stats of a replay pass", below); the routes give it back as `details` when it is there and a reader skips every key it does not know. If the database stops answering the history is *unavailable*, not the server: the routes answer 503, the feeder waits, one line in the log says so, the server looks again every minute and says once when it works again.
- **The record** (layout `v` 1): `id`, `ended` (seconds since 1970 UTC, the time in the recording's name), `map`, `game` (the version that recorded it), `turns`, `seconds`, `finished` (the rules ended the match; false: a player left it or the room's time ran out), `quitter` (the seat whose quit ended the match, `null` when none did), `mode`, `format`, `draw`, `result`, `computers_only`, `seats` and `rows`. `mode` is the room's game mode, `"highest-score"` (the original's game) or `"187"` (network protocol 17, [`GAMEPLAY.md`](GAMEPLAY.md#187-a-game-type-of-the-remake)). `format` is how the match began: `1v1` (two seats), `2v1` and `2v2` (a pair as a team against a seat, or against another pair), `ffa3` and `ffa4` (free for all; a team that the roster could not make is free for all too); a match of one seat is `solo` and has no winner. `result` is `draw`, `cut` (a player left, the time ran out, or the recording stops before the rules ended the match) or `decided`. A seat is `{"seat" 0 - 3, "color" ("Green", "Red", "Blue", "Black"), "colour" (the same value: the older spelling of the key, see the note below), "name" (what the player typed, `""` when nothing was typed: the readers show the color), "bot" (a computer player's level, `"Easy"`, `"Medium"`, `"Hard"`, or `"Bot"` when its name says none, `""` for a person), "score", "killed", "lost", "hatched", "bombs_planted", "bombs_defused", "fires_lit", "left", "winner"}`. A row is one line of the results screen, `{"seats" [one or two], "score", "killed", "lost", "hatched", "winner"}`, an alliance's numbers added up; the rows are ranked, and the first is the winner unless the match is a draw. The food and bridge counters of the engine are never fed (they are in the state hash) and are not kept. **Mode 187 has no food and no score:** the engine's score there is the kills, so a record keeps the kills as `score` (the ranking value, always equal to `killed`) and the pages must not show it as a score.
- **Who won.** The rule depends on the game mode, and every record says which one it was played by. **Highest score** (the original's game): the winner is decided by the **score**; a tie in score goes to the **kills** (enemy ants killed); equal kills too is a **draw**. Losses and hatched ants never break a tie. **187:** the last side with ants or eggs wins outright, whatever the kills (the engine's own end rule, `MatchResult::standing`); when nobody is left alone (the clock ran out, or every side ran out at once) the **most kills** wins, and equal kills is a **draw**. An alliance is one side whose numbers are added up, and both its seats are marked `winner`. A side whose **quit ended the match** is last whatever it scored (as on the screen) and the other side wins, never a draw; a seat that dropped out of the match before the end (60 seconds without a sign of life, or a quit that did not end the match) has no row and is marked `left`. Nobody is `winner` in a draw. **How this maps onto the engine's ranking:** `MatchResult::rows()` supplies which seats make a row (an alliance both confirm is one row) and puts the quitter last and, in 187, the side left first, but it ranks by score only and breaks a tie by the seat of the screen (the original gives the tie to the local team; a record has no local team, so it would be the lower seat) and knows no kills. The rule above is therefore written out in `rank_history_rows()` (`history_record.cpp`), which re-ranks the engine's rows (a stable sort, so equal rows keep the engine's order) and decides the draw; the tests make up the engine's result for every tie, in both modes (`test_history_record`). A match with no person in it (`computers_only`) is the server's own bot match or an arena file; "Bot (Hard)" in a recording's name for a seat is a computer, and a person who types exactly that is counted as one too.
- **The recording's state.** Every answer says whether the recording can still be watched: `"recording": "watch"` (the file is kept and this build plays it, and `"file"` names it), `"old"` (kept, but recorded by other simulation rules: it is listed under "Earlier versions" of the watch page and cannot be played by this build; `"file"` too) or `"removed"` (the 30 days are over, or the owner deleted the file; no `"file"`; a file that is kept but damaged is reported this way too, because the public door cannot give it either). The state is not stored: it is whether the file is in the replay store's list. The answers also say `keep_days` (30), the days a recording is kept.
- **Asking for it.** On the public door, and on the control interface behind the secret: `GET /history` lists, `GET /history/<id>` gives one record. The list is `{"history": [...], "count" (the records that fit the filters), "total" (all of them), "offset", "limit", "keep_days", "sim_rules"}`, newest first, each entry a record without the bombs and fires of its seats, with `recording` and `file`. The query holds the filters of a page, each key at most once: `limit` (1 - 100, default 50), `offset`, `sort` (`new`, `old`, `score`, `kills`, `hatched`, `long`, `short`; a match's score, kills or hatched is the best of its seats', a tie keeps the newer match first), `format` (`all`, `1v1`, `team`, `ffa`), `result` (`all`, `decided`, `draw`, `cut`), `who` (`all`, `people`, `computers`), `rec` (`all`, `watch`, `old`, `removed`), `color` (`all` or a seat that took part: `green`, `red`, `blue`, `black`), `mode` (`all`, `highest-score`, `187`) and `q` (part of a map's name or of a name, at most 40 characters, any case; a seat with no typed name is searched by its color and a computer by `Bot (Level)`; `%`, `_` and `\` in the text are themselves, not wildcards). The words are lower case and exactly as written here (`color=black`, not `Black`). **The older spelling.** The filter was `colour=` and each seat of a record had a `"colour"` key before the project wrote `color` everywhere; so that bookmarks, scripts and pages in a browser's cache go on working, the server still accepts `colour=` (the same filter, the same words; `color=` and `colour=` together, or either one twice, is a 400 that names `color`) and still writes `"colour"` next to `"color"` in every seat, with the same value. The pages read `color` and fall back to `colour` only when a server of an earlier release sends no `color`. A later release removes the older spelling; use `color`. A word that is not one, a key twice or an unknown key is a 400 that names the key; nothing is guessed, and nothing a request says is ever part of the SQL. **A list cannot hold up the server:** the database runs on the server's one main thread, so a visitor's list is *time boxed* (15 ms; the owner's 100 ms) and the public door has a *budget* of query time (about 50 ms for each second, 100 ms in a burst); a list that runs into its box is a 503 `that search is too heavy for the server: narrow it`, one with a query that is asked when the budget is used up a 503 `the match history is busy: try again in a moment`, answered without asking the database (the list with no query at all is not held back by the budget, only by its box). The site's nginx adds a low allowance and a short cache for lists with a query ([`SERVER.md`](SERVER.md#replays)). A name is printable ASCII (the protocol's rule: the game makes a `?` of any other character), so a search needs no more than that; a byte above 0x7E in a query is a 400. The item is the whole record with `recording`, `file` and `keep_days` added; an id that cannot be a match, or one that is not in the history, is 404. The routes and limits are in [`SERVER.md`](SERVER.md#replays).
- **Taking one out.** Only the owner: `DELETE /history/<id>` on the control interface. If the recording is still there a marker row stays (in `history_markers`) so that the match is not counted again from it; the marker is deleted by the hourly look when the recording is gone too. Without a recording nothing stays. The public door cannot delete.
- **The stats of a replay pass** (`details`). The play that counts a match (`replay::play()`) also counts what the engine does not total: `ants_replay/match_stats` is a collector that `play()` is given as its hooks (`Hooks::before_command` for the orders, `Hooks::after_tick`, called after every tick before the engine's queues are cleared, for the rest). It only watches, through the engine's public readers (the counters, the world after every tick, the record that the engine keeps of an ant that is gone, with the team of its last damage, the cue of a bomb), so a match plays out in the same hashes with or without it (`test_history_details`) and the totals never depend on it; no engine code is touched. It counts the score and the kills of every seat every 5 seconds; who killed whom and when; the hit points each seat took and dealt; the raids of Thieves on hills; the power-ups taken; the food carried home and the points banked; the bombs that went off; when a seat had no ant (an egg hatches one for free) or was out; and the orders of every seat by minute and by kind (move, attack, bomb, fire, bridge, raid, other special order, stop, hatch, team) and by the type of ant they name. `ants_server/history_details` makes the JSON of it (layout `v` 1: its header comment lists every key), at most `kDetailsMaxBytes` (5,000, whatever the match: the series have at most 48 points, the lists of kills and raids at most 30 events, and a text that is still too long loses the lists, then points, then combat and economy, and one that is still too long is the marker below) and `GET /history/<id>` gives it under `details` (the list leaves it out). The feeder writes it in the same transaction as the record; a record that was counted before the pass existed gets it when its recording is still kept and plays here (the backfill: after the new files, newest first, at the same pace); a recording that is read and cannot be played (it does not play out here, or the pass cannot count it) leaves the marker `{"v":1,"n":1}` so that it is not tried again, and the page says only the totals were kept; one that could not be tried at all (its map is not in the maps folder or the community folder, or the replay store would not give it) leaves nothing and is tried again when the server starts again. The totals of a match are written whatever the pass does. What the pass cannot tell (it needs an event sink in the engine, outside the state hash, which is a later change): what caused each hit (a blow, a bomb, a fire wall) and which ant struck. An older recording (other simulation rules), a removed one and a live match have no stats.
- **The names stay.** The names that players typed are public wherever the public door is on, as in the recordings ("On the game server"), and a record keeps them for good, not for 30 days. The pages that tell players what is kept must say so before they show the history (the front page footer and the two name cards say it: "Recordings are kept for 30 days. Results and names are kept for good and are public.").

## The match pages

The history above is what three pages of the site show (`web/matches.html`, `web/match.html`, `web/live.html`; their look is `web/matches.css`, the code that they share `web/history_page.js`). They read the server's public door and nothing else (`GET /history`, `GET /history/<id>`, `GET /maps`, `GET /live`, and a recording only when it is asked for), they need no account, and every name that a record or the door carries is put in as text, never as markup. The addresses: `/matches.html` (and `/matches` and the old `/watch.html`, which are 301s to it), `/match.html?id=<id>` (the id is the recording's file name without `.antsrep`) and `/live.html`; `/live` and `/history` are the game server's own JSON routes, so the pages cannot have those names. A "Matches" and a "Live now" link are in the footer of the front page, the game page and the three pages, and a "Matches" button in the header of the front page and of the game page.

- **Every match** (`/matches.html`) is the list of `GET /history`, newest first, 25 to a page, as lean cards: the map's picture (the six originals' own; a map of the players has the picture of the map list, `GET /maps`, or else the address that its name makes, `AntsMapPicker.thumbFor`; the dark square when there is none) and name, the format (1 v 1, 2 v 1, 2 v 2, Free for all; a pill for mode 187 only, the original's game being the default), "Cut short" or "Draw", the day and time in the visitor's own time zone, the length, and one box for each **side** (the record's rows: an alliance that both seats confirm is one side, whatever the format said at the start) with the names as stored ("Pip (bot, Hard)", "Bot (Hard)" for a computer player that an earlier version stored with no name, the color word where nothing was typed), its score ("12 kills" in mode 187: its score is the kills) and **Won** on the winner. The state of the recording is on the card: **Replay**, **Older version** (kept, recorded by other rules, cannot be played by this build) or **Replay removed**. The whole card is the link (**Stats & replay**, or **Stats** when there is no replay to show). Over the cards: a search (a map or a name; the server's own `q`, at most 40 printable ASCII characters), **All matches / With people / Computers only**, and Format, Result, Replay, Color, Mode and Sort by (the server's words, `docs/REPLAYS.md` "The match history"; a phone keeps the search, the three buttons and the sort in view and the rest behind **Filters**), with a chip for every filter that is not the default and **Clear all**. A sort by a count (score, kills, hatched) shows that count on each card (in mode 187, whose score is the kills, a sort by score shows the kills). The address is the state (`?who=people&format=ffa&sort=kills&q=pip&page=3`: only what is not the default, in the server's words), so a link can be sent and Back works; the page is not loaded again for a filter. **What it asks the server:** the plain `GET /history` (the newest 50, cached by the site, not held to the server's budget) for the first two pages of the default view, and one query for every filter, search, sort and later page (`limit=25&offset=...`: the site allows two of them a second for each address, so a search waits 450 ms after the last key, a choice of a select, a button or a page waits 350 ms and the choices that come within that time are one request and one step of the history, and a look that is late for a newer one is dropped). A busy server (503) or one with no history (404) is said in the server's own words with a **Try again**, and a page past the last one (an old link) says so with **Back to the first page**. A button **N live now** is in the header while a match is being played (one look when the page opens).
- **One match** (`/match.html?id=<id>`) shows the whole record. **The result:** the map, the format, the day and the length, who won and the score of every side, and **Show replay**, **Download file** and **Copy link**. **The scoreboard:** a score-share bar (a segment for each side), and for every seat the Score, Killed, Lost, Hatched, Bombs set, Defused and Fires lit with a bar for the size of each against the best seat, "Won" and "Left early" marks, and the total of a side of two (a phone has a card for each seat and each side of two instead of the table). Mode 187 has no Score column. **About this match:** the map and its size, the mode, who played (people and computer players), the format, the length and the turns, when it ended, how it ended (the rules, cut short, a quit), the version that recorded it, and the id. A recording of an older version has no button, only the words (who made it and that this version cannot play it) and **Download file**; one that is gone says "Replay removed: recordings are kept for 30 days. The stats below stay." (a match that is not in the history, for instance one that ended a moment ago and is not counted yet, says so and offers its replay and the list.) The page is a list of **sections**, each a panel that is built from the record or is nothing (`SECTIONS` in `match.html`). The stats of the replay pass are three of them (`web/match_stats.js` and `match_stats.css`, which read the record's `details` through `AntsHistory.detailsOf`: a plain object or nothing, every number read as a number, every seat as 0 to 3, every name as text): a **band of highlights** under the result (up to four chips that link to their section: first blood, the lead, the comeback, the busiest seat, or "No ant was lost", said only when the scoreboard also has no ant lost, since an ant that died with no team to blame is in no kill; no chip links to a section that is not on the page, so the raids chip of the picture comes with the Combat section), **Over time** (the score of every seat and the kills so far as charts of inline SVG with no library, a shape for each seat besides its color, a strip of who had the most on the score box with a side of two named and two-toned, first blood marked, and the facts under them: last kill, changes of the lead, the comeback, the best run of kills, a seat that had no ant left) and **Activity** (a strip of squares of the orders of every seat in every minute, the busiest minute of each ringed, a table of the orders by kind, the busiest seat and minute). A match with no `details` (an older version, a recording that was removed before it was counted, a match that has just ended, a pass that could not count it) has none of the three and one line under the scoreboard that says why ("More stats"); the older-version line under the result says that the totals are complete. The numbers for combat (who killed whom, damage, raids) and for ants and economy (power-ups taken, food, bombs, the types of ant used in orders) are kept in `details` and have no section yet; every ant that hatches is a Worker and the game has no bomb throw, so there is no "types hatched" and no "thrown".
- **The replay in the page.** **Show replay** opens the game page itself in a frame (`/play.html?replay=<file>&embed=1`, the page's mode with the picture and the bar only: no header, no footer, no stats, no way out of the page) and **only then** is anything of the game fetched (the wasm and its data, about 9 MB the first time, which the browser keeps; and the recording): the page makes the frame in one place, `setReplay`, when it opens, and **Hide replay** (or the game's own Quit inside the frame, which tells the page; the frame's address opened on its own has no page to tell, and its Quit goes to the list) takes it away and frees the game; there is one frame at most. **Fullscreen** (where the browser has it for an element) and **Own page** (a new tab) are in the replay's header. The page and the frame are one origin and carry the two cross-origin isolation headers that every page of the site carries (`Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Embedder-Policy: require-corp`, [`docker/nginx.conf`](../docker/nginx.conf): a new `location` with an `add_header` of its own drops the ones of the server, so each repeats them), which is what lets the frame run under the page; a phone's frame is small (turn the phone, or use Fullscreen).
- **Live now** (`/live.html`) lists the matches that run now: the server's `GET /live` every 10 seconds while the page is in front (the matches of 30 seconds or more, the newest 50), each with a red **Live** mark, the map, who plays, the time it started, how long it has run and **Watch live** (`/play.html?live=<id>`, "Watching a replay" below). A running match has no stats (the door gives only the recording so far, which the game page plays; its scores are in the picture), so the page has none; when it ends it is counted into the history by the feeder and its card appears in the list (and a match page that is asked for before that says so). A server with no live door (404) is told in a sentence, and an empty list says that nothing is on.
- **The stats on the replay page.** The game page in replay mode (not a match that is being played, not the frame of a match page, and only a recording of the server's own store) asks `GET /history/<id>` once and, when the server has the record, gets a **Stats** button in the header (wide screens; a phone has a row under the controls instead) that opens a panel with the winner, the numbers of every seat, the total of a side and a link to the match page. It is closed at first, and its closed row (a phone's too) says nothing of the result, so it does not tell who won before the viewer asks; the numbers are the final ones: they do not follow the picture. The panel is `AntsHistory.replayStats` and `web/replay_stats.css` (the file also holds the frame mode's rules).
- **Tests.** The shared code runs with node on tables, and again on broken copies, which the checks must refuse (`tests/scripts/web_history_check.js`, `web_history_pictures_check.js`, run by `test_web_matches.py`, which also reads the pages: where they ask, with which words, that the frame is made in one place only and when). The stats sections run on a small fake of the DOM with the real helpers, on tables, on damaged details and again on broken copies (`tests/scripts/web_match_stats_check.js`, run by `test_web_match_stats.py`). `test_web_matches.sh` (opt-in) shows the pages in a real browser against a fake door and a stand-in for the game: the cards, every filter with the request that it makes, the pager, a busy server, every state of a match (the stats, none, damaged ones), that nothing of the game is asked for before **Show replay**, then one frame in embed mode under the site's headers, and the stats of the replay page. The routes and the headers are in `tests/scripts/web_routes_check.py` (run against the image by the CI).

## Watching a replay

The pages are the site's own: the **Matches** and **Live now** links of the footer and the **Matches** button of the header (["The match pages"](#the-match-pages); a new tab on the game page, so that a match being played there goes on; not shown while a replay is watched, whose header has "All matches") and the **player**, which is the game page opened as `/play.html?replay=<file>` (or `?live=<id>` for a match that is being played, below). Nothing is switched on and no account is needed.

- **The player** is the game itself in a replay mode (`--replay FILE`; the web page fetches `/replays/<file>`, writes it into the game's file system and starts the game with it). The game plays the match from the file on its own engine, shows the whole map (no Fog of War), and throws away every order of the HUD, so a visitor cannot change the match; the picture is for looking, not for clicking (**nothing can be picked**: no click, drag box, corner marks, Move and Stop buttons, order markers, ant voice, Ctrl+A / H / N / P or inspect panel; the pointer over it is the plain arrow, and the minimap, the edge of the screen and the wheel work as in a match: `HUD::set_view_only`, set for a replay alone). Above the picture: the map, the time, the players, and the buttons **All matches**, **Copy link**, **Stats** (when the server has a record of the match: "The match pages"), **Download** and **Fullscreen** (on a phone: **All matches**, **Full** and **More**). Under it: play and pause (the space bar too), **Back 30 seconds** right of it (a left-pointing double triangle with a small 30; a press jumps the playhead 30 seconds of game time back, never before the start, through the timeline's own jump, so a match that plays keeps playing, a paused one stays paused and the speed stays; it is not there for a match that is being played, `?live=`; a forward button and a shortcut key are not built; the page's half is `rewindControl` in `web/replay_page.js`), the timeline (click or drag to jump to a moment; the arrow keys jump 10 seconds, Home and End go to the ends), the time and the length, the **Auto camera / Manual camera** button ("The camera", below), the speed ½×, 1×, 2×, 4× and 8×, and a **Picture** button that opens a small window with the picture's four shapes (4:3, 16:10, 16:9, 21:9: the visitor's choice, remembered, 16:9 at first; [`PLAY_IN_BROWSER.md`](PLAY_IN_BROWSER.md#a-169-picture-that-fills-the-page)). The tag **REPLAY 1×** (or **Paused**, or the live words below) sits just above the bar, never over the picture (the bar's top margin makes the room: about 25 pixels, which a short window takes from the picture's height). A jump rebuilds the match from the start on the same engine (the game does it in slices, and a veil with a bar says "Jumping to 3:20…" when it takes a moment). At the end the game's own results screen shows and the play button becomes **Watch again**. In fullscreen the bar lies over the bottom of the picture, with the tag above its left end and a small tab on its top edge, and goes away by itself three seconds after the last touch of it (or the last move of the mouse) while the match plays (it stays while the match is paused); a swipe down on it (not on the timeline, which keeps its own drag) or a tap on the tab hides it at once. **A finger on the picture never calls the bar**, so a tap or a drag of the map leaves the picture clear; a tap, or a swipe up, along the bottom edge calls it (a tap calls it in its click, so that it does not press the button that the bar then has under the finger; a strip about 56 pixels high with nothing drawn on it, there only while the bar is away and the last touch was a finger, so that a mouse keeps the game's edge; on a phone with gesture navigation the very bottom belongs to the system, and a touch that starts a little above it works). The first time in a visit that the bar goes away after a finger was used, a note says for 3 seconds how to bring it back. A mouse, a pen and the keys call it as ever.
- **The camera** (`include/ants_app/auto_camera.hpp`; a pure model that the application feeds while the recording plays: nothing of it reaches the simulation, so no hash moves). **Auto camera** (the default, lit) **locks on the biggest action and follows it**; **Manual camera** leaves the picture where the viewer put it. **What it reads** is what the engine already says while it plays, for every seat at once (a replay has no Fog of War; a world that had one would be read only where it is revealed): the hit points of the ants (a fall is a hit, an ant that is dead is a death) and the cues with a place (the blow of every kind of ant, which names the ant that struck, the dust ball of a brawl, a Thief diving into a hill and coming out, a hill's score going down or up, a Fire ant's beam and burst and the fire burning out, a bomb going off or picked up, a bomb taken to be defused, a base alarm and a raid, which the engine gives to the seat they are about and the camera places at that seat's hill, an ant falling in the water, a power-up dropping, a bridge going up, an ant picking food up). **The action score.** Every such event has a weight and fades away over 5 seconds: a kill 14, a bomb 10, a fire 5 for each of its two cues, a theft, a bomb taken to be defused or a hill losing points 6, a hit 2, a blow 1, banked food 2, the rest between 0.25 and 3 (food carried, a bridge and a power-up the least). An event of an ant belongs to the ant and moves with it. The score of a place is the sum of the events within seven tiles of it, and 12% more for every fighter after the first (up to 2.2 times) when ants of two sides or more are fighting there, so a team fight beats a lone scuffle with the same blows and a bigger event of one side only. **The lock.** The picture goes to the place with the most action once that has a score of 12 (a hit, a blow, a bomb or a fire alone does not; a kill with its hit does, and so does a brisk fight or a theft), centres on it and follows it: every tenth of a second the middle of the place is taken again from where its ants are now, so the picture goes along with a fight that moves. It stays at least 7 seconds; after that it moves on only to a place at least 1.5 times as busy as the watched one (and never for less than 1.5 times the score of 12: a fight that is cooling is not taken from by a place that has only just engaged), or lets go when the action it watches has been under a score of 3 for 3 seconds, and then stays where it is until something engages it again (when nothing happens nothing moves, and the first seconds of a match have the picture on the first hill). It never moves the zoom: a wheel zoom keeps Auto, at the viewer's zoom, and the picture glides back to the place. **How it moves.** A critically damped spring (about 0.6 s to arrive, at most 1400 world pixels a second, no snap, no overshoot), so a switch is one smooth pan, and a view that is still moving goes on from its speed. All its times are the viewer's seconds, not the match's: at 8× a place still holds for 7 seconds of looking, and from 4× up only the big events count (kills, thefts, fires, bombs). Every number is in the first block of `auto_camera.hpp`. The minimap shows a ring where the busiest place is now (the camera is there once it has locked on it; while a busier place begins during its 7 seconds the ring is already on the new place and the picture is not yet): whole while the camera is Auto, dashed while it is Manual. **Taking the camera** makes it Manual: the pointer at the edge of the screen or a drag on the minimap that moves the picture, and two fingers that pan it (more than 10 pixels within 300 ms: the pixel or two that a pinch drifts is not taking); the wheel and the pinch only zoom, which keeps Auto, at the viewer's zoom. The button returns to Auto: the picture glides to the busiest place now (else to the last thing that happened) and locks on it. The first time in a visit that the camera is taken a note says "You have the camera. Press Auto camera to follow the action again." The button's choice (not the taking) is remembered on the device (`localStorage` `ants.cam`, `auto` or `manual`). In the bar it sits between the clock and the speeds (the word goes where the bar is narrower than 900 px, and in fullscreen only the icon stays); on a phone it has a row under the speeds, which it shares with the Picture button. Page and game: `ReplayControl::SetCamera`, `ReplayValue::Camera` and `CameraTaken`; the page's half is `cameraControl` in `web/replay_page.js`. What the camera does **not** know: a moment before it starts (the picture arrives about a second after a fight begins, and a theft or a death at the very start of a match has nothing before it), where an order was aimed, or a seat's point of view (not built).
- **The page and the game talk through two exported functions** (`ants_replay_get(what)` and `ants_replay_do(what, value)`, the enums are in [`include/ants_app/replay_view.hpp`](../include/ants_app/replay_view.hpp)) and two calls of the game to the page (`window.antsReplayReport(info)`, what the file is or why it cannot be shown, and `window.antsReplayLeave()`). The state, the turn and the speed are the game's; the page only draws the bar.
- **A file that cannot be shown says why** on a card over the picture: recorded by an older version (it names both, and offers the file), recorded by a newer one ("Load the page again"), gone ("Matches are kept for 30 days"), or one that cannot be played (the map is missing, the file is damaged, the match does not play out the same here). A name in the address that is not the shape of the server's own file names is never fetched.
- **The same game in the same browser as ever:** **fullscreen holds the mouse (the pointer lock) as the game does** (same request on entering, same release on leaving or Esc, the same setting `ants.pointerlock`, the edges and corners of the picture scroll the map), and the bar stays clickable: the game's cursor is the pointer, and while it is over the visible bar the page makes the mouse events for what is under it (a press and release on a button click it, the timeline drags even beyond the bar) and draws a small arrow over the bar (the game's own cursor is under it); while the mouse is locked the bar lies inside the picture's box (on a screen of another shape than the picture's it would otherwise be partly out of the cursor's reach), the outermost pixels of the picture stay the game's (the edge scrolls with the bar up) and the wheel over the bar does not zoom. Known limits while locked: a button has no hover look, and the bar moves into the picture when the lock is taken or let go (a focused button loses its focus). Code: `barPointer` in `web/replay_page.js`. Leaving the page never asks "Leave the game?".
- **A match that is being played** is watched as a replay whose file is still growing: no new connection and no new protocol, only the public door ([`SERVER.md`](SERVER.md#replays)). The **Live now** page ("The match pages") reads `GET /live` every 10 seconds while it is in front and shows each match with a red **Live** mark and its length so far; **Watch live** opens `/play.html?live=<id>`. The player gets `GET /live/<id>` (the recording so far), starts the game with `--replay --replay-live`, and every 4 seconds fetches the file again, writes it over the game's copy and calls `ants_replay_do(Extend)`; the game takes it when it is the same match with more turns and plays only up to 40 turns short of its end, so the picture is about 10 seconds behind the players. The tag above the bar says **LIVE about 10 s behind**, or how far behind a paused or moved playhead is (**Paused · 0:59 behind**), **Jump to live** goes to the present, and Download waits until the file is whole. A feed that fails says "The live feed stopped. Trying again…" and goes on trying. When the match ends the door answers 404 with the name of the kept file: the page fetches it, Extends once more and goes on as a replay of the whole match (its address becomes `?replay=<file>`, "The match is over. It is now in the list as a replay."); a match that was not kept ends where the game holds it (`LiveOver`, "The match is over."). A link to a match that has ended has a card with **Watch the replay**, and a link to a match that is not live (or an id that is not the shape of the server's, which is never fetched) says "That match isn’t live". What the door says is shown as text and never as markup. `tests/scripts/test_web_live.sh` (opt-in) checks these pages, and the tag and the fullscreen bar of the player (`--only bar`), in a real browser against a fake door and a stand-in for the game.

**Which files play: `sim_rules`.** A recording plays only on a build that computes the match the same way. That used to be the network protocol's number, which moves whenever the wire format does (v0.12.0 made it 16 for lobby rooms without touching the simulation), so every protocol bump would have stranded the files before it. The head now has its own field, `sim_rules` (a small number, `replay::kSimRules`, 5 now), which changes **only** when a match plays out differently (a golden hash moves: the engine, the map reader, the original's tables). A file plays when its number is the one of its game mode that the build plays: the original's game, 5; **game mode 187** ([`GAMEPLAY.md`](GAMEPLAY.md)) has the number 6 (`replay::kSimRulesMode187`), so a build that plays both says "5 and 6" and a build from before the mode, which plays 1 only, refuses a 187 file for its rules number instead of playing it as the original's game. A file made before the field has none: a table in `replay.cpp` maps the protocol numbers that are known to play out the same way (15 and 16 → 1, the number of the rules before the bombs of a map file) and any other number is unknown (0), which no build claims. The server's list says it for every file (`sim_rules`, and the list's own top-level `sim_rules` is the number of the build that serves it), and the page shows the files of another number in a box "Earlier versions", with Download and no Watch. When a change makes matches play out differently, raise `kSimRules` in the same change: `test_replay` RP7.1 - RP7.3 play a reference match and fail when its final hash moves and the number does not (and when the number moves for no reason), so a stranded file cannot slip in; RP7.7 does the same for a reference match of mode 187 and the number 4. Raising it adds the old protocol numbers to nothing: the old files stay in the list under "Earlier versions" until they are 30 days old.

## Matches of computer players

`bot_arena --save-replays DIR` (the tool of [`BOTS.md`](BOTS.md)) keeps every match that it plays as a replay of the server's kind in the folder `DIR`, through the server's own store (`ReplayStore`: the names `ants-<MAP>-<date>-<time>Z.antsrep`, tmp file and rename, the 30 days and 100 MiB limits). The head says venue "bot arena", no Fog of War and the display names of the bots ("Bot (Medium)", "Bot (Hard)"), so the list shows them as "Green (Bot (Hard))" like the bots of a room, and the player plays them back to the hash of the arena's own match (the tool's self-test checks this). A match under 30 seconds is not saved, as on the server. **How they reach the site's list:** point `DIR` at the server's replays folder (`replays` in its results volume). The arena's own store deletes nothing (its limits are the largest ones: 3650 days, 4 GiB), so pointing it at the server's folder does not cost the server a file at the stack's limits (the one exception would be a server set to 4096 MiB with its folder full to the brim). The server looks at that folder again every 30 seconds when its change time moved (`ReplayStore::rescan`): a file that was put there is listed (one that changed in the last two seconds waits for the next look, so a copy that is still growing is not taken for a damaged file; a file that could not be read or changed its size is read again), a file that was taken away is forgotten without deleting anything, and the server's own limits then apply to the files from outside too: a file older than 30 days that is copied in is deleted again at once. A store that opens the folder deletes the half-written `.tmp` files of a crash, but not one that changed in the last two seconds (`settle_s`): that is the write of the other program, which renames it in a moment, so the server and the arena can open the folder at any time. Two writers of the same name in the same second could still replace each other's file (a rename replaces on Linux), and never run two arenas on one folder at the same time.

The game server plays matches of computer players of its own too (`--bot-match-every-min`, [`SERVER.md`](SERVER.md#matches-of-computer-players)): a room with no person in it, free for all or in teams (the head of the file holds them, as for any match), at the normal speed, recorded and listed like any room's match, and shown in the list of the matches that are being played while it goes on. Those matches are what the "Live now" box of the list shows when nobody else is playing. The stack runs no other program that plays bots: `bot_arena` is run by hand.

## The file

A `.antsrep` file is a row of chunks, like a PNG: a reader skips a chunk that it does not know (unless its first letter is upper case: then the file is refused), every chunk has a checksum, and a file that stopped in the middle still plays up to its last whole chunk. The numbers are little endian. [`include/ants_replay/replay.hpp`](../include/ants_replay/replay.hpp) has the exact layout; in words:

| Chunk | Holds |
|---|---|
| `HEAD` | the format number; the protocol number (information); the simulation rules number `sim_rules` (what a build plays a file on, "Watching a replay"); the game's version and build; "local game" or "network game"; the map's file name and its hash; the seed; the seats that play; Fog of War; the names; the teams that the match started with; the game mode (head field 17, one byte, **written only when it is not the original's game**: a file of the original's game has no such field and is byte for byte what it was before the modes); the seat of the machine that wrote the file |
| `CMDS` | the orders in the order in which the engine was given them, each with its turn; one chunk for every 30 seconds of game time or 4,096 orders |
| `hash` | the low half of the engine's state hash after every 100th turn (every 5 seconds of play) |
| `ENDS` | the number of turns, whether the rules ended the match, and the state hash at the end. A file without it is incomplete: a copy that was cut short (a download that stopped, a file that was truncated), because the game writes a file whole, when the match is over or left, or a snapshot of a match that still runs (`live`, below) |
| `live` | only in a snapshot of a match that still runs ("On the game server"): the number of turns the match had run when the snapshot was made, which can be more than the last order and the last hash say. It is optional and its tag is lower case, so a reader that does not know it skips it. A reader that does takes the file's length from the largest of its last order, its last hash and this number, and refuses a file that has two of them, one of the wrong length, one with fewer turns than its last order or hash, or one together with an `ENDS` chunk |

An order is the network's own wire form (the one a room sends, [`NETWORK_PORT.md`](NETWORK_PORT.md)): its type, who gave it, the tile, the ants that it names by number. **Turn t** is the t-th tick of the engine: the orders of turn t are given first, in the order they stand, and then the tick runs (a turn is 50 ms). Orders at the last turn's number come after the last tick: a Quit that ends the match is one.

**The rules number** that a file is played on is `sim_rules` ("Watching a replay"; `replay_tool info` shows it with the protocol number that the room spoke). A file is played only by a build that plays its `sim_rules` (the original's game 5, game mode 187 the number 6; the numbers 3 and 4 were theirs from the bombs of a map file, v0.12.9, to the loader as the original's, v0.12.10, and 1 and 2 before); another build still reads its header, and the message names both numbers and the game that made the file. **The mode and the number go together**: a head with a mode that is not 0 names the rules number of that mode, and a head that names the rules of mode 187 names the mode, so a file with one and not the other (or a mode this build does not know) is no file (the writer refuses to make it and the reader refuses it, with the field named). The recorder takes the mode from the match's Start (the server's referee, the network game's Start, the local game's engine), and the player makes its engine with it before the first tick. The list of the server and the tool say the mode (`"mode": "187"`, `replay_tool info`: "game mode 187"), and a mode-0 file shows no difference. (Before the field, the network protocol's number stood for it, and a file without the field is read through the table of protocol numbers that are known to play out the same way.) **The map** is found by its file name in the folder of the shipped maps (`--maps-dir` names another) and must be the same file: another file under that name is refused with both hashes. On the web the page fetches a map of the players from the site before the game starts ([PLAY_IN_BROWSER.md](PLAY_IN_BROWSER.md#players-maps-in-the-browser)).

**Size:** a match of computer players is a few KB (4 KB for two and a half minutes of four of them on the smallest map), a long match of people tens of KB. A recording that would pass 1 MiB is not kept (the console says so).

## The tool

```bash
cmake --build build --target replay_tool
./build/replay_tool info    match.antsrep      # what the file says: map, seed, seats, teams, length, orders (no map needed)
./build/replay_tool verify  match.antsrep      # plays it and compares every hash in the file and the final state
./build/replay_tool orders  match.antsrep      # plays it and lists every order
./build/replay_tool orders  match.antsrep --seat 1 --type bomber     # only the orders of Red that name a bomber
./build/replay_tool orders  match.antsrep --csv > orders.csv         # a table for a spreadsheet
```

(`build\replay_tool.exe` on Windows.) `--seat N` is 0 Green, 1 Red, 2 Blue, 3 Black; `--type` is worker, bomber, fire, thief, combat or swimmer; `--maps-dir DIR` says where the maps are. The exit status is 0 when the file was read (and, for `verify` and `orders`, played to the end with every hash right), 1 when the file is refused, its map is missing or the match does not play out the same here, and 2 for a wrong command line or a file that cannot be read. A file that stops early plays as far as it goes and says so; if it holds no hash either, `verify` has nothing to compare the match with and says UNVERIFIED (exit 1) instead of OK.

`orders` prints one line for each order:

```text
TINY.LVL, seed 5: Green, Red, Blue, Black; 3000 turns (2:30.0)
  time  turn  seat   order  place    ants      from     result
0:00.6    12  Green  move   (12,12)  3 Worker  (9,8)    ok
0:00.7    14  Red    move   (18,18)  3 Worker  (21,21)  ok
...
291 orders: Green 57, Red 92, Blue 65, Black 77
```

- **time** is the game time of the order (minutes:seconds.tenths since the first tick), **turn** the turn number, **seat** the color, with the name when the seat has one ("Red (Bot (Hard))").
- **order** is `move`, `special`, `attack`, `stop`, `hatch`, `team offer` / `accept` / `refuse` / `withdraw` / `leave`, `quit` or `dropped out`; **place** the tile of a move, special or attack, or the other side of a team order.
- **ants** are the ants that the order names, by type ("3 Bomber, 1 Worker"), read off the engine as it stood when the order was given: an order names its ants by number, and only the engine knows what an ant is. Ants that were gone, never were, or belong to another seat are counted as "not there" (the engine leaves them out). **from** is the tile where the first of those ants stood.
- **result** is what the engine said: `ok`, `ignored` (nothing for it to do, for example every ant named was gone) or `refused`.

With `--csv` the same lines come as a table (`time,turn,seat,name,order,x,y,ants,from_x,from_y,result`; the text cells are in quotes). A text that begins with `=`, `+`, `-` or `@` (a name in someone else's file could) gets a `'` in front, so that a spreadsheet shows it as text and never takes it for a formula.

A **special** order is what the ant's type does with it ([`CONTROLS.md`](CONTROLS.md#mouse-controls), [`GAMEPLAY.md`](GAMEPLAY.md#special-abilities)): a Bomber plants a bomb at the place or defuses one, a Fire ant lights a fire wall or puts out a blaze, a Swimmer digs a bridge on water or demolishes one, a Thief raids a hill. For a group of workers, combat ants or mixed ants it is a plain move. After the table the tool counts the special orders by the type of ant that got them: "special orders by ant type: Bomber 12, Swimmer 3" is how to see at once whether a player bombed with bombers and dug bridges with swimmers.
