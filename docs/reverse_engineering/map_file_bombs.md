# Bombs that a map file holds: the layer-2 ids 129 .. 132

What the original does with a bomb tile that the map file itself places, and what the remake does since v0.12.5. Read from the decompilation, the movement reports in `movement/` and Table 4 of `ants.chd` ([`../chd_table4_animations.json`](../chd_table4_animations.json)); the original was read, never run. The rest of the combat and ability rules are in [`../GAME_REVERSE_ENGINEERING.md`](../GAME_REVERSE_ENGINEERING.md) 5.36 and 5.37.

## What a bomb is, and its colour

`FUN_01008bc6` is true for the layer-2 ids `0x81 .. 0x84` and nothing else. Table 4 names them: **129 `redbomb`, 130 `greenbomb`, 131 `blackbomb`, 132 `bluebomb`** (a cell's tile value is the id of its Table-4 animation). The bomb a bomber plants is one of these four tiles, chosen by the planter's colour (colour ids 0 black, 1 blue, 2 red, 3 green: red 129, green 130, black 131, blue 132), so a bomb from a file is the same object. The four ids are in the original's forced-graphic table, so they are drawn whatever the map's dictionary calls them; the editors mostly leave the entries `.` (61,456 of the 61,766 bomb cells of the community library). The remake keeps a planted bomb as the id `100 + the team index` (0 green, 1 red, 2 blue, 3 black) and turns it into the original's 129 for the minimap (`minimap_object_id`).

## What the original does with it

- **Who sets it off:** any ant of any type and team, the owner included, that ends a step on the tile or lands on it. The test is the id alone (`WalkStep` `FUN_0101b8cb`, the landing and the end of a walk; the arrival `FUN_0101ccaf` for the order `0xa`; [`movement/03_walk_step_arrival_and_stop.md`](movement/03_walk_step_arrival_and_stop.md) 12, 172, 756). A bomb is not solid. Clicking a bomb tile with any ant gives the order `0xa` ([`movement/06_orders_goto_and_group_dispatch.md`](movement/06_orders_goto_and_group_dispatch.md) 266).
- **What it does:** the bomb is removed at once (SetTile to `0x7ffe`, which also clears the cell's footprint, its owner word and **its layer-1 solid bit**, row 0 excepted: `FUN_0100744f` -> `FUN_0100660c(row, col, 0)`). The ant takes two hits credited to the owner. One trigger in five is a dud (`rand() % 100 < 20`): the ant is not thrown, it freezes under the burn overlay and is stunned when that ends. Otherwise it is thrown 4 tiles opposite its facing with the `gb` flight, and `bombex` plays; landing on another bomb sets that one off. There is no blast area: only the ant that stepped on it is hit.
- **The owner** is the second word of the layer-2 cell ([`movement/04_occupancy_passability_and_blocking.md`](movement/04_occupancy_passability_and_blocking.md) 83, 435), the file's third 16-bit word (`properties` in the remake's parser), kept verbatim (`FUN_010069d8`). The game writes the planting team's index there; it is a team index, not a colour, and the colour is the tile id alone. A bomb from a file holds whatever the editor left: of the 61,766 bomb cells in 208 of the 558 community maps, 46,873 hold 0, 6,126 hold 1 and 8,767 hold larger leftovers (257, 513, 769, 1025, 4864, 22616). A value of 4 or more is a team that does not exist: the kill credit tests `team < 4` and credits nobody (`FUN_0100cd9f`), and the path rule compares the word with team indices, so it matches nobody.
- **Who avoids it:** the path rule R7 (`FUN_0101fbd4 - 0x101fc14`, 04:187): a bomb tile is refused as a path step only for ants of the owner's team, or when the owner is the ally field of the local viewer's team (the field is 4, "no ally", when there is no ally: an owner word of exactly 4 therefore blocks everybody who has no ally). Enemy bombs and bombs with another number are walked onto freely; the order `0xa` to that very tile is always allowed.
- **Defuse:** a bomber's special click on a tile that cannot take a bomb but holds any bomb (any owner, any colour) is the order 9; after the `abdb` clip (about 1.1 s) the bomb is removed without an explosion ("Bomb defused."). Other ant types cannot.
- **Fog and minimap:** an unexplored bomb is not drawn (the decision table of 5.33) and the minimap shows the terrain under it, whoever owns it (5.55).
- Ten of the bomb cells have the anchor bit (word 0 bit 0) clear; the program only tests the id, so they are bombs all the same.

## What the remake does

- `Grid::init_from_level` turns every layer-2 cell with an id of 129 .. 132 into a bomb of the tile's colour: `interactive_id` = 100 + the colour's team (129 red = team 1, 130 green = 0, 131 black = 3, 132 blue = 2), `interactive_owner` = the cell's word (0 .. 4 as it is, anything above 255 = nobody), no anchor, **whatever the dictionary says** and without being an obstacle overlay. Its solidity is what the file's layer-1 solid bit says, as for every object (the loader's other rules are unchanged). The renderer draws it through the grid by its id (the colour), not as a static object, and not after it went off; the minimap and the map picture show the terrain under it; the bots see it as every bomb.
- Everything else is the code of the planted bomb, unchanged: the trigger (`movement_system.cpp`), the victim (`bomb_victim`: two hits to the owner, the 20 % dud, the 4-tile throw, the chain), the path rule R7 (the walking ant's own team and its ally, where the original asks the local viewer's ally), the defuse of any bomb. Comparing these with the original's code as read above, **the only difference found was the layer-1 solid bit**, which `Grid::clear_bomb` now clears like SetTile (row 0 excepted; a planted bomb lies on a cell that was not solid, so only file bombs on solid cells are affected: 1,332 of the placed cells).
- A food object whose anchor lies on a bomb cell replaces the bomb with its stage tile at load (SetTile on the anchor, as in the original): `Bombz Away` has 896 cells of id 131 and 895 bombs.
- **Rules and protocol numbers.** The change moves the plays of the 208 maps that hold such cells and no other. By the rule written next to `kProtocolVersion` (any change of how a level is read, even one that shows only on some maps) the network protocol is 18 (nothing on the wire changed), and by the rule of [`../REPLAYS.md`](../REPLAYS.md) the replay rules numbers are 3 (the original's game) and 4 (game mode 187); recordings of rules 1 and 2 are an earlier version's.
- Not changed, found on the way: the remake's own bomb ids 100 .. 103 are also tile ids of the original (`dok_bok3`, `qh_screen`, `death1`, `death2`) and `TileCell::has_bomb()` answers for them; no map of the library has them on layer 2. Mutation checks, the sweep and the tests: `tests/test_sim/test_file_bombs.cpp`, `tests/test_app/test_file_bombs_render.cpp`.
