# The countdown before a match (network protocol 21)

The start of a match used to be fast: the "Get ready" dialog of the original, 5 s ([`NETWORK_PORT.md`](NETWORK_PORT.md), "Protocol 12"). In a dedicated server's room of two or more people the host now holds the first turn **30 s** and the game shows a **countdown card** over the map with the game's own chat live and a **Fullscreen** button, so that the people in the room can talk and go fullscreen before the match begins (what the player sees: [`VIEW_AND_HUD.md`](VIEW_AND_HUD.md), "The countdown card"; the page: [`PLAY_IN_BROWSER.md`](PLAY_IN_BROWSER.md); the server's setting: [`SERVER.md`](SERVER.md), `--start-countdown-seconds`). This page is the protocol and the machines' side; it has its own page because [`NETWORK_PORT.md`](NETWORK_PORT.md) is at its size ceiling (`tools/check_hygiene.py`).

Request (2026-10-15): "after the game is started from the lobby it starts too fast: a 30 second countdown before the game starts, with the chat active during, and a Fullscreen button". No rule of the simulation, no golden hash and no lock-step rule changes: the host holds the first turn longer, and says so.

## The change in the network

* `kProtocolVersion` goes from 20 to **21**. **Begin** is two bytes now, `[Begin][seconds]` (`encode_begin(seconds)`, `decode_begin`): how long the host holds the first turn after the match began, 0 .. 60 (`kMaxCountdownSeconds`; a value above is cut on the way out and refused on the way in), 0 for the plain 5 s "Get ready" dialog of protocol 12. The one-byte Begin of protocol 20 is no Begin; a Hello of 20 is refused as ever (`VersionMismatch`), so no machine meets the new one.
* **Who gets it.** A dedicated server's room whose setting `countdown_s` is not 0 and in which **two or more people** play (`kCountdownMinPeople`; the computer players are not people) holds the first turn `countdown_s` seconds (`kMatchCountdownSeconds` = 30, the server's `--start-countdown-seconds`, the control interface's `"countdown_seconds"`, see [`SERVER.md`](SERVER.md)). `Room::start_lobby` decides when it starts the match: it tells the lobby (`HostLobby::set_countdown_seconds`, which makes the Begin say it) and keeps the same seconds for the session (`HostSession::Config::start_delay_ms`, which `Room::begin_match` gives it). A room of one person (with or without computer players), a game on the local network (`NetGame::begin_match`), a game on this computer and a machine that is given a match that runs (the Begin that follows its Loaded says 0) keep the 5 s dialog.
* **The countdown starts when everybody has loaded**: it is the Begin's, so the wait after START is the pages' loading and then 30 s.

## What a machine does

* `NetGame::Event::countdown_seconds` (from `ClientLobby::countdown_seconds`) tells the application; `Application::begin_net_countdown` keeps the moment (`net_time_ms_` + seconds) and `HUD::start_match_countdown` makes the start dialog the **countdown card** ([`VIEW_AND_HUD.md`](VIEW_AND_HUD.md), "The countdown card"): the count of the seconds left, the colours and who plays them, the chat open. The count is the machine's own clock from its Begin (the first turn arrives when it arrives: at 0 the card says "starting..." until it does, and the first executed turn closes the card, as it closed the dialog). The count follows the network's clock of the page (the frames and a hidden page's wake-ups advance it, at most a second at a time), so a page that was hidden for long may show more seconds than are left; the first executed turn closes the card whatever it says.
* **Chat** was relayed by the host before the first turn all along (only commands are discarded, protocol 12); what changes is that the HUD lets the chat's text (the characters come as text input, never as key events), Backspace, Enter, F9 - F12, the All and Team buttons and Quit through while the card is up. A command before the first turn is discarded without a violation as ever, so nothing of the match can be done in the wait.
* **Fullscreen**: the card leaves a place (`HUD::countdown_button_rect`); the web page lays a real button over it (`web/countdown_button.js`, which `web/shell.html` calls: a browser grants fullscreen only to a click on a real button), the native game draws its own.

## What does not change

* **The simulation, the turns and the recording.** No turn exists before the first one, so the sealed turns, the state hashes and a replay are what they are for any start; a match with a 30 s wait and one with the 5 s dialog, given the same orders at the same moments after their first turn, seal the same bytes (tests `test_lockstep` S2.18). The room's `run_ms` limit counts the seconds before the first turn, as it counted the five. The live board lists a match after 30 s of turns, so the countdown does not count there; `/busy` counts the room as a match from its begin.
* **A seat lost in the countdown pauses the match** as in the dialog (the schedule slides; the card is closed for good, the pause overlay and the vote take its place; the resume countdown follows the return, then the first turn): the rest of the 30 s is not kept (S2.19, RJ1.28). A player who leaves is dropped in the first turn as ever. A server that restarts in the countdown brings the room back paused (its record holds no turn) and resumes with the resume countdown.
* **The Quit button** works in the countdown: before the first turn no Quit command can be sealed, so the player leaves for good (`Application::confirm_quit`).
