## Where this differs from the design, and why

- **The match runner is a library file, not part of the tool.** The design put all of `bot_arena` into `tools/bot_arena.cpp`. The tests (AI4.x) and the tool need the same code, so `play_match` / `replay_commands` live in `ants_ai` (no threads, files or clock: it builds for the web too) and the tool adds the command line, `std::thread`, the clock and the report. `ArenaSpec::factory` lets a test seat a bot that is not in the registry (the selftest's scripted walker, the tests' walkers).
- **`BotView::score()` stays the number of the score box** (a team's score plus its ally's, never below 0): the design wrote "the individual score", but B1's review decided (AI2.16, BOTS.md) that a view shows what the boxes show; nothing in B2 needs the individual score (nothing hatches before B5).
- **`BotView::build` takes a `const MapInfo*`** (default null) instead of a reference: B1's tests build views by hand without a map and must keep working unchanged.
- **A copy of a `BotView` drops the borrow** (empty grid, `predict_ack` 0, `has_pending_path` false). The design only said "grid() borrowed, valid inside think()"; making the copy lose the borrow means a bot that keeps a view for later cannot read a stale engine, and costs nothing.
- **The engine's walking rule is not `TileCell::is_passable`.** The design (and my first version) used it plus the queue-row flag. The conformance test AI1.9 found at once that the engine walks over a tile whose obstacle-overlay flag is set when the LVL file does not mark the tile solid (TREASURE (52, 41)): `MapInfo::walkable` now mirrors `can_enter` R1, R3, R4 and R5 (terrain, the 4 x 4 mound of any hill, `Grid::is_solid_object`, other teams' queue rows, the last two by geometry because `is_corridor_team_locked` is not set by the current grid). The design's "4,790 random pairs" agreement did not include that tile; with the old rule the test fails (mutation `overlay`, below).
- **The approach cost is exact**: the best walkable neighbour of any cell of the pile plus the engine's own step cost onto the cell (the design added a constant 20), and a pile whose cost reaches 8,000 (the path finder's limit) has no approach. (Since the review the cell itself must also be one that the engine lets an ant step onto: not water, not inside a mound, not on another live team's queue row; and the field it adds to starts from every walkable tile of the hill's queue row, not from the middle one.)
- **Piles with two objects on one anchor**: `PileInfo::cells` is empty for the object whose cells a later object took, `bite_index` says which object loses the units (found and tested in AI1.20, see below); the design only said "keep distinct indices".
- **`approach_now`** (new): the click tile of the start may no longer be food after a stage change; a bot that re-targets a worked pile asks again.
- **Suite numbers**: the view, map and arena tests are new files of the existing `test_ai` executable (suite 2.20), the arena's self-test is the next free number, 2.21.
- **Options the design did not list**: `--no-wall-time` (so that a report is bit-reproducible: wall times are in the JSON by default, as asked), `--maps-dir`, `--quiet`, `--map shipped` (all six), default seats = four standard bots at medium level, default threads 1.
- **The reference numbers of docs/BOTS.md were NOT regenerated**: `worker` and `standard` still run the idle bot, so `bot_arena` can only show zeros. The prototype numbers stay labelled as prototype measurements until B3. What `bot_arena` does reproduce is everything about the maps: lengths, reachable points, trip costs.

## Findings about the engine (no behaviour changed)

- `TileCell::is_passable` and `is_obstacle_overlay` are not what the engine walks by; `can_enter` / `step_cost` are (see above).
- The path finder fails for a goal whose best path costs 8,000 or more (`kFailF`, tested before the goal test), also when the goal is in the same component; and it is not optimal (no decrease-key).
- `SimulationEngine::tick()` returns before `current_tick_++` on the call that ends the match, so after the end `current_tick()` is one less than the number of calls. A replay (and any "play N ticks" loop) must count calls: `RecordedCommand::step`, `ArenaResult::steps`. (The replay of a full match failed at its last call until this was found.)
- Harvest: an ant bites the FIRST object of the table that has the pile's anchor (`start_harvest`), the points of the bite are those of the object found by the clicked cell, and the cells belong to the LAST object of the table (`food_object_at_cell`). AI1.20 runs it with an ant: 4 bites take the 4 units of the first object, each earns the last object's 50 points, the last object keeps its 4 units for ever. On the shipped maps this only touches the two TREASURE corner anchors, which no hill reaches on foot.
- A pile's footprint is the footprint of its current stage tile; `approach_now` finds the cell to click now. On TINY's pile 12 (5 cells at the start) the click tile of the start is no longer food for some hill before the pile is eaten (AI1.18).
- The HUD draws an egg tray of at most nine eggs; the view gives the exact stock (a harmless deviation, noted in the header).
- The engine's path finder never generates a tile of ROW 90 (the neighbour routine writes 90 as its "off the map" marker and the search skips every neighbour with that row), so on a map of 91 or more rows nothing can be walked into row 90 and the map is cut in two there. The original does exactly this (Capstone: `Ants.exe` `0x1019b23 cmp ax, 0x5a`; decompilation line 18335); it is now in `docs/GAME_REVERSE_ENGINEERING.md` and modelled by `MapInfo::walkable` (AI1.31). No shipped map is taller than 60 rows.
- `PlayerMatchStats::food_deposited`, `food_stolen` and `food_lost` are never incremented by the simulation: they are 0 in every match and only the state hash reads them (as 0), so they cannot be fed without changing every golden hash. The arena counts points banked and raided itself (`ArenaSeatResult::banked`, `raided`), and its report (format 2) no longer carries the three dead counters.
- A test world (`init_test_world`) has no solid row 0 (a map from an LVL file does): a wall that is meant to close a world has to include row 0.
- `kill_unit` removes an ant at once (a test fixture): the pair tests clear the field with it, and a fresh engine per pair costs 15 to 150 microseconds.

- Every existing suite passes unchanged (`./run_tests.sh`); the build is clean with `-Wall -Wextra -Werror -Wsign-conversion` on top of the project's `-Wpedantic -Wconversion -Wshadow`.

## Review

An adversarial review of B2 (four reviewers: the view, `MapInfo`, the arena and the tool, the tests and the documents; every finding reproduced by a second reader) found 37 points: one was rated MEDIUM after verification (the arena's result fields were only ever compared with 0), the other 36 low. Two were wrong statements in this file (the version number, the speed of the new tests) and were corrected first. The other 35 are fixed in the release after v0.0.87. Nothing in the simulation changed and no golden state hash moved; the existing tests that changed are named below.

**How each fix was proven.** Every fix has a test that fails without it. For the code, each fix was undone one line at a time (a mutant), the library rebuilt and the suites run: 75 mutants, 74 of them caught by a test written for it (a few also by an older test). The survivor is only plumbing: the line that copies `raided` from the ledger into the result (`r.raided = ledger.raided(seat)`; no match of the shipped bots has a raid to show, and the ledger itself is held by AI4.13). The log of the run is not part of the repository; the catching tests are in the table. One more mutant (the match limit checked after the jobs are built) cannot be run: the self-test would ask for 28.8 million jobs, so it only ever ends by a timeout; its test is the refusal with nothing allocated (`capacity() == 0`). The mutation run was made in three passes as the code settled (a first pass of the library and tool, a second for the ones that did not build under `-Werror`, a third for the arena after the ledger was rewritten); sources of the last pass are the ones in the patch except for one added assertion and one comment. The mutants that the review itself found alive (the arena's turn boundary, canonical order, controller seed, seat order, the replay's checkpoint count and last-step test, the news and audio queues; in the tool: `same_match`, the repeat loop, `ok()`, the latency and tick options, JSON quoting, the thread pool, the replay field of the report) all die now. Statements in documents were fixed in the documents. Timing-dependent behaviour (AI1.7) was shown under load: 60 runs next to 32 busy processes on a 10-core machine, the old criterion (mean of 300 looks) failed 2 times and the new one (fastest of 300) never, on the same samples. The undefined shift of `roster_of` was shown with UBSan (`arena.cpp` compiled with `-fsanitize=undefined`: "shift exponent 32 is too large" before, silent after).

### Where the fix differs from the proposal

- **`predict_ack` was not made faithful.** `SimulationEngine::predict_order_ack` is the lock-step client's feedback for a click (v0.0.46) and a const query of the engine; its special-target rule is the original's cursor test. Matching `apply_command` exactly would mean reproducing `go_to`'s classification, goal adjustment, approach tile and occupancy inside `ants_ai` (private to `ants_sim`, and the very thing the conformance tests exist to avoid duplicating) or changing the engine's prediction for every human click. Neither is cheap, so the contract is documented and pinned by a differential test; a bot that wants the answer checks the next view.
- **`food_deposited` cannot be asserted equal to the score**, because the engine never increments it. `banked` (rises of the score between ticks, with the price of an egg taken off first) is the arena's own number (`ScoreLedger`); with a hatching bot `banked == score + 200 x hatched` is asserted, and AI4.13 holds the ledger against a hatch command, the egg the engine starts by itself for a team that lost its last ant (it charges min(score, 200) too), and a deposit in the same tick. The report format is now 2.
- **The lunchbox value is a constant (30)**, the middle of the 10 to 50 that a bite or loot is worth; any constant would do, and a bot that wants to rank lunchboxes cannot.
- **The trip model's numbers moved** because of finding 6 (the start from the whole queue row makes every approach cost up to one step cheaper): the model now fits the nearest piles to -0.5 to +12.0 percent where it was +4 to +23.
- **`ANTS_TEST_FILTER=text`** is new in the test harness (`ai_test.hpp`): only the cases whose title contains the text run; without it nothing changes.
- The tool's self-test writes temporary files and sets a file size limit for the length of one call (POSIX only): the tool may, `ants_ai` may not.
