# Site statistics: the numbers of the front page (state of the branch `site-stats`)

Handover notes of the branch: what it does, what was checked, what is left. Short on purpose; the details are in the tests and in `docs/NETWORK_PORT.md` ("The site statistics").

## What the branch does

- **`SiteStats`** (`include/ants_server/site_stats.hpp`, in `ants_server_core`): `online` (a match that ran at least 600 ticks (30 seconds of play) and ended, any room, counted when `RoomManager::take_ended` tells its end: a start-and-quit loop cannot pad the number) and `local` (a single-player game that a browser reported), each as the last 24 hours (24 hourly buckets on the server's clock) and in all, plus `since` (the UTC day the counters were made). At most 120 reports count in any 60 seconds. One file, `site-stats.json` of `--results-dir`: written whole to a temporary file, fsync'ed (`_commit` on Windows) and renamed, at most every 10 s while something changed and at a clean stop; a write or sync that fails removes the temporary file and leaves the old file whole; a file that is no usable file is put aside as `.broken-<seconds>`.
- **The door** (`ants_net/ws`): `GET /stats` beside `/busy` (`more_status`), and one POST path (`post_path`, `post_action`) that takes no body and no query and answers 204; the parser stays pure and says `posted`, the listener runs the action once.
- **`ants_server`**: the wiring in `main.cpp` (count every ended room, the two endpoints, `save_if_due` each pass, `save` at the stop).
- **nginx**: `/stats` (GET, twenty a second per address with a burst of 100, answered from a cache of five seconds) and `/stats/local` (POST, sixty a minute per address with a burst of 20, a request that the browser says is cross-site is 403, never a body passed on); neither passes on a header of the visitor (only `Host`, `Connection` and `Content-Length: 0`).
- **The web game**: `Application::set_on_local_match_started`, told at the first tick of a game on this computer (once for each match, never in a match of the network); the web build sets it to `antsReportLocalGame()` of `web/shell.html`.

## Not verified, and worth knowing

- **The cache directory** `/var/cache/nginx/ants_stats` is made by nginx when it starts (the web container runs nginx as root, as in every compose file here); an nginx that cannot make it does not start, and `nginx -t` says so. The docker tests are skipped without docker, and the real-server one without a built `ants_server` or where a container on the host network cannot reach this machine (Docker Desktop).
- **The web image was not built here** (the Emscripten link, the page in a real browser): the first `antsReportLocalGame` that reaches a server is the CI's web image and the owner's browser. `tests/scripts/web_stats_check.js` runs the function with a fake `fetch`, nothing more.
- **Per-address limits behind another proxy.** The site's nginx sits behind a reverse proxy that ends TLS (`README.md`, `docker-compose.stack.yml`) and `docker/nginx.conf` has no `real_ip` setting, so `$binary_remote_addr` there is the proxy's address unless nginx is told otherwise: the limits are then the whole site's. They are sized for that (20 a second for the numbers, which the cache answers; 60 reports a minute; the server's own cap of 120 a minute is the bound that matters). **For the owner:** the nginx limits are per visitor only when nginx sees the visitors' addresses; behind a proxy, `set_real_ip_from <the proxy's address>` and `real_ip_header X-Forwarded-For` make them per visitor (not in the file: the proxy's address is the owner's).
- A room that the owner names `site-stats` would write its result file over the counters' file (`<code>.json`); the next start puts it aside. Not guarded.
- A match that a stop of the server ends (a room without a restart record) is not counted.
- The cap's ring (the last 120 counted reports) is in memory only, and a restart starts it afresh: the first minute after a restart can count 120 more. The nginx limits are in front of it.
- The folder is not synced after the rename: a power cut can bring back the file as it was before the last save, never a half file. The Windows branch of the sync (`_commit(_fileno(f))`) is built by the CI only.
