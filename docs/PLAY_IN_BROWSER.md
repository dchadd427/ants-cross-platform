# Play in the browser

The game runs in a modern web browser, as WebAssembly, with nothing to install: **[Play Ants Online at beta.playants.org](https://beta.playants.org)**. This page says what that site does. To build and serve it yourself, see [`BUILD_AND_RUN.md`](BUILD_AND_RUN.md). The game is developed and tested in a Chromium-based browser (the engine of Chrome and Edge); Firefox and Safari have not been tried. A phone can play it too: [`TOUCH.md`](TOUCH.md).

## The front page: Home, and a room one press away

**[beta.playants.org](https://beta.playants.org)** is the front page, the lobby (`web/lobby.html`, served at `/`). It used to be a separate Play online page; that page's address, `/four.html`, now redirects here with its query. The page is built like the game's own menus: the black boxes and teal buttons of the setup screen and the original's help sheets. The pictures are in `web/front/` (the four ants are one sheet, `ants.png`, made from the game's assets by `tools/front_page_art/`). **START!** is not a picture but a real button in the same teal, drawn by the browser so that it stays sharp at any size; the font is Libre Franklin, under the SIL OFL. The page is built from the approved lobby cards 1 to 18.

There is nothing to set up first. The page opens on **Home** ([Home](HOME_SCREEN.md)); **Quick host** makes a **room** on the game server and seats you in the first color, as its host, under a name the page picked (or the one this browser used last); the link is there to send. Nothing is played until the host presses **START!**. The Room, from top to bottom, shows:

- A line of numbers in the Menu (the footer holds it in the markup and is not drawn on either screen), for example "3 matches being played · 7 players online · 1,284 games played (21 today)". "Today" means the last 24 hours. It counts what the game server knows: the page reads its `/stats`, else `/busy` for the live part, else it shows no line ([`SERVER.md`](SERVER.md#busy-and-stats)). It looks when the page opens and every 30 seconds while the page is visible.
- **A Discord button** ends [the bar of the other pages](SITE_NAV.md) (the front page's Menu has the link): the project's Discord invite in a new tab, nothing sent before the click ([Legal](#the-legal-page)).
- A strip with the button **Rejoin it**, only while there is a match to go back to ([below](#rejoin-your-match-code)), and a strip for the page's notices ([below](#the-notices)).
- **Your room**, inside Home in the Games list's place ([Home](HOME_SCREEN.md#the-room)): the header (the room's name, **Share** with the room code on it, **Rules** and **Leave**); under it the four colors as four slim rows (four tiles, two by two, on a phone held upright); beside them, in one column, the map, the game type and the big button (**START!**, a guest's **READY**) with one line under it; the rules (who can join, Fog of War, Direct connection) in the **Rules** sheet; and the room's chat in the chat box, in its own tab. The room has no Picture row: the shape of the picture is a row of the game's settings menu (below). START! hands the game the shape exactly as the rule of "Which shape" says: `?aspect=` in the room's address, else the shape that the browser remembers from an earlier choice for the way the phone is held now (`ants.aspect.v3`), else nothing, and the game page then starts in Automatic's shape.
- **How it works**, a button in the Menu that opens the lobby's rules in a few lines beside the original's two help sheets. The footer (not drawn: the Room has no footer, and the Menu has its links) also has the links to **Matches** (every match played here, with its stats and replay; the front page's Menu has it), the sprites and sounds, the changelog, GitHub, feedback and the [Legal page](#the-legal-page); and the version and build. Under the links, centered, is the maintainer's yellow **Buy Me a Coffee** button: a picture that the browser fetches from Buy Me a Coffee's own server (the one thing on the front page that comes from another site, with `crossorigin="anonymous"` because the page is cross-origin isolated; the Legal page says so).

### Your room

- **The link and the code.** The link is `https://<site>/?room=k7m2xq`; the code is shown in two groups, `k7m 2xq`, on the **Share** button ([below](#the-rooms-code-and-its-create-block)). **Share** copies the link and says "Copied!" for a moment; on a phone (a window up to 700 px wide or up to 500 px high) in a browser that has one it opens the browser's share sheet instead, and a browser that can copy neither shows the link in its own box to copy by hand. There is no field with the link on the page. Players who open the link take the next free color and show up in the room at once. The page remembers the room for this tab (session storage `ants.lobby`), so a reload takes your seat back. A new tab has a room of its own; a tab that was duplicated holds the same seat, and when the copy takes it the first says "This room was opened in another window, so it is closed here." with a button, **Use this window**, that takes the room back.
- **Going away and coming back.** **While the page holds a room** (the page holds one; not once it is on its way to a game) the links to the matches, the masthead's, the footer's and the Menu's **Matches**, open in a **new tab** (`target="_blank"`, `rel="noopener noreferrer"`: the maintainer's decision of 2026-11-17, a change of the rule that only the links that leave the site did), so the room's tab stays connected for as long as a replay is watched; with no room they are plain links of the same tab. **Watch** in the Games list follows the same rule ([`HOME_GAMES.md`](HOME_GAMES.md#games-quick-join-quick-host-and-the-public-room)), and the Home of such a tab (Matches, Watch) closes that tab and returns to this one ([`SITE_NAV.md`](SITE_NAV.md#a-tab-that-the-front-page-opened)). A page that is left anyway (the browser's own Back, a typed address, a closed tab) is the case below. The server holds the seat of a page whose link ended for a minute, with its color and its lead ([`SERVER.md`](SERVER.md#lobby-rooms)). A page that goes writes the seat (room, key, name, time) into this browser's local storage (`ants.lobbyseat`, taken away as soon as a page has the seat or the seat is given up), and a page that opens within 55 seconds of that, in the same tab or another, takes the **same seat** back with the key: the host leads again, nobody joins, the page holds the room on Home, and the Games list calls the room **Yours** instead of offering Join. A page that is on its way to a game writes none. After more than a minute the seat has ended and the next person leads: the key finds no seat, the room takes the page as a newcomer, and a strip says so ("Your seat in this room ended while you were away, so you joined again. Sam is the host."; the room is no longer the page's own). A room that is gone says "That room is gone, because everybody left, so this one is yours now.".
- **Direct connection** is every player's own switch, a row of the **Rules** sheet (off by default, kept by the browser; `web/front/lobby_direct.js`, [`P2P_HINTS.md`](P2P_HINTS.md)): "Can lower delay. Players you connect to can see your IP address." The first time it is turned on a short explanation asks (**Turn it on** / **Keep it off**: it changes only on the answer); turning it off again is one press. Off, every connection to the other players of a match goes through the site's relay and no address reaches another player. The choice goes to the game page (`--direct on`); the countdown card of a match then shows `relay` or `direct` where it said `in` beside each other person once a channel is up. A browser with no WebRTC shows no switch.
- **Invite only | Public** is the host's switch, the first row of the **Rules** sheet (a guest reads it, and the **Rules** button says the state, "Public" or "Invite only"; "Fog" follows it while fog is on): a public room is in the **Games** list ([Home](HOME_GAMES.md#games-quick-join-quick-host-and-the-public-room)). **Have a code?** in that list opens **Join by code**: a code as shown or a room link (`k7m 2xq`: blanks, capitals do not matter; up to 32 letters, digits, `-`, `_`); your name goes with it and you get the first free color. A code that no room has says "There is no room with that code." and makes none.
- **The four colors** lie as the four hills lie on the Small and Treasure maps: **Black** top left, **Green** top right, **Red** bottom left, **Blue** bottom right, here as four rows one under the other in that order (a color's row is the same on every width, but on a phone held upright they are four tiles, two by two). A color's number is its seat (Green 0, Red 1, Blue 2, Black 3), so a new room fills Green, Red, Blue, then Black. Each row shows the dots (the host drags with them), the ant, the color's name and what it is: a **person** (tagged **Host** and, on your own color, **You**), **Open**, a computer player (**Easy**, **Medium** or **Hard**, with its name, "Pip (bot, Hard)": a computer player is always shown as one) or **Closed** (a color that stays out of the match; the plan calls it Nobody). No line of help is under a color.
- **What the host can do.** A color that no person holds is a button with its choice ("Open", "Hard bot"): one press opens a short menu (**Open**, **Easy bot**, **Medium bot**, **Hard bot**, **Closed**; `web/front/seat_menu.js`) that sets it, and on a phone held sideways the whole row is the button; on a phone held upright a tap on any tile opens that color's sheet, which has the same choices ([Home](HOME_SCREEN.md#the-room)). Drag a player onto another color to move them (a free color is taken, a taken color swaps places, and the team goes with the player); on a phone held sideways, tap a player's dots and then the color (held upright, the Color row of the player's sheet). The small **Remove** button beside another player's name asks "Remove Priya from the room?" with **Remove** and **Keep** (the focus is on Keep, Esc is Keep), and opens the color again; the removed player gets a room of their own with a note that says why, and can come back with the link. The host's own color, a computer player and an open color have no Remove, and neither does a player's screen. A player cannot change anything but their own name .
- **Teams**, with three or four players: every color that plays has two small buttons, **1** and **2**, at the right end of its row. Two colors on the same team start the match allied; with four players the other two colors are the other team (their button shows it), with three the third color plays alone, and with no two colors on one team it is free for all. The line under START says which when nobody is waited for ("Free for all. For a team, put two colors on the same team." or "Teams: Green + Red against Blue + Black."); a guest reads a small "Team 1" tag. A team is two colors at most: pressing the button of a full team changes nothing and says "Team 1 has two colors already. Press one of them to take it off first." A player's screen shows the teams but cannot change them. On a phone held upright the buttons are in the color's sheet and a tile shows the team as a tag.
- **The map** is one card: its picture, name, kind and the map-info line of the setup screen, and the host's **Change map** button, which opens the list of the six originals and the players' maps. **Treasure** is the map until the host chooses another. The host's choice goes to the room and to the other players' screens.
- **Ready up** ([`READY_UP.md`](READY_UP.md)): a person who is not the host has the big button as their **READY** (a switch: pressed is ready) and a mark (**Ready** or **Not ready**) shows on every row; the host does not ready, pressing START is the host's Ready, and a computer player is always ready. START! is off until every person has said it, and the line under it says whose Ready it waits for ("Waiting for Wren to ready up", "Everyone is ready.").
- **The line under the big button** is one line that says what matters most now. START! on its way ("Opening the game for everybody."), no room, a color that was tapped ("Now tap the color where Sam goes."), a refused team, who is not back from a match, whose Ready START waits for; else who is in ("1 of 4 in. Open colors stay empty if nobody joins.", with three or four the teams in place of the second sentence); with nobody else and every color closed "A game for one." A guest reads "<host> starts the match." under READY. On a phone held sideways the line is left out (the Players tab's count says who is in).
- **When the host leaves**, the player who has been in the room longest becomes the host and everybody reads "Juniper left. Sam is the host now." (the new host: "Juniper left, so you are the host now. The map, the colors and START are yours."). Teams that needed the one who left clear. Computer players never become the host. When the last player leaves, the room closes about a minute later, so a reload does not lose it; a link to it then says "There is no room with that code. Check it, or ask the host to send the link again." on the name card, which offers **Start a room of my own instead** (a link never makes a room of its code). Only a page that had a seat in the room and finds it lost later (a server restart) makes the room again under the same code ("That room is gone, because everybody left, so this one is yours now, with the same map.").

### The room's code and its create block

A room code is **only a name**: six random letters and numbers of `abcdefghjkmnpqrstuvwxyz23456789` (no `i`, `l`, `o`, `0` or `1`, which are easily mistaken), made by the page. The screens show it in two groups of three, `k7m 2xq` (the lobby's header, **Rejoin it**, the name step of a shared link, the field of **Join by code**); a link, a field's value and the game's arguments keep the plain `k7m2xq`. A typed or pasted code ignores blanks and capital letters, and a link with capitals leads to the same room. Any code of 1 to 32 letters, digits, `-` and `_` is valid: a code that was made some other way, or by an earlier page (`demo-small-2p-x7k2`), joins like any other and names nothing but itself.

What a room is made of can travel in its **create block**, which the game sends in its first Hello: the map, the seats, the teams and whether a full room waits for its leader's START. The server reads the block of the first Hello of a code only (a room that exists keeps its own choices), and a Hello for a code that has no room and brings no block is answered "There is no such room on this server." The lobby needs none of these: it speaks protocol 16 (`web/front/lobby_net.js`), whose Hello carries the map for the room it makes (a plain visit, and a page that had a seat and lost its room, so that the room is made again) and carries nothing for a link or a typed code, which only join. Nothing on the front page writes the block's parameters any more (they belong to the addresses of the earlier pages, and to a game page that somebody opened with them); they are those of `web/shell.html`, which gives the game one whitelist each and only with a valid `join`. In an address they are written `&roommap=<key>`, `&roomseats=<n>`, `&roomteams=A%2BB`, `&roomleaderstart=1` and `&platform=<word>`, after the room's plain code:

| Parameter | Value | The game's argument |
|---|---|---|
| `roommap` | `tiny`, `small`, `medium`, `gauntlet`, `treasure` or `islands`, in any case; none: the server's own map | `--room-map <key>` |
| `roomseats` | `2`, `3` or `4` | `--room-seats <n>` |
| `roomteams` | two different seats 0 to 3 as `A+B`, written `0%2B1` in a link; none: free for all | `--room-teams <A+B>` |
| `roomleaderstart` | `1`: a full room waits for its leader's START instead of starting by itself | `--room-leader-start` |
| `platform` | `windows`, `macos`, `linux`, `android`, `ios` or `other`, with or without `browser-` in front, in any case: what the room shows beside the player (cosmetic). The pages make none and do not look at the browser: only an address's word counts | `--platform <word>` |

### START!

- The host presses **START!**. The match does not begin at once, because each player's browser has to leave the lobby and open the game: the server keeps the request and starts the match when everybody is in a game. Meanwhile the lobby is frozen (nothing can be dragged or pressed), START! says "Getting ready…", and each player's color shows "Opening the game…" and then "In the game". A link opened now gets a room of its own: nobody joins while the games open.
- Each page goes to the game page of its seat: `/?join=/ws&room=<code>&seat=<n>&name=<name>&aspect=<shape>` (only after a pick), with the key of the seat written to this browser first (`ants.rejoin.<room>.<seat>`, [below](#rejoin-your-match-code)), so the address has no key. The game seats the computer players of the plan, leaves the **Closed** colors empty and starts. The game's loading screen, quick help and the "Get ready" dialog come first, as in any match. With **two or more people** in the room the dialog is a **30 s countdown** (below), which starts when every game has loaded.
- A game that does not come in within 90 seconds ends the wait: everybody is back in the room, as they left it. The host reads "<name>'s game did not come in time. Everybody is back in the room, as you left it. Press START to try again." (the first part is the server's own sentence); every other player reads "The match did not start, so everybody is back in the room. <host> can press START to try again." The host can then **Remove** the player whose game never opened.
- **A game for one**: with nobody else in the room and no computer player (every other color **Open** or **Closed**), START! takes this tab to a game on this computer (`/play?map=<key>&name=<name>&aspect=<shape>` (only after a pick), or `?mapfile=<file name>` for a map of the players: no server, no room, no bots, no teams, and only your colony on the map). The page leaves the room first. The line under START says the same on every map.
- **After a match** the room is opened again for a rematch: [After a match](#after-a-match), below.
- The server's own rules apply as ever: a match is made for 2 to 4 seats, **the first player in the room can start early with START once at least 2 players are in** (a computer player counts; the lobby's host can start alone against computer players) **and every other person has said Ready** ([`READY_UP.md`](READY_UP.md)), a running match takes nobody new (only a player who comes back to their own seat), and no computer player plays with Fog of War ("Bots cannot play with Fog of War.", the server's words). The game's own setup screen is the original's host screen with the START button ([`GAME_REVERSE_ENGINEERING.md`](GAME_REVERSE_ENGINEERING.md) section 5.50); the lobby makes its press for the host, and in the waiting room **T** (or a click in the chat box) opens a line to say something to everybody.

### After a match

When the rules end the match (every machine shows the results), the game server opens the room again at once: the same code and link, the same host, colors, computer players, teams, map and game mode, and a seat kept for each player of the match whose game ran in a browser ([`SERVER.md`](SERVER.md#lobby-rooms) has the server's rules). Nothing of the network protocol changed (protocol 21): `web/front/rematch.js` and `rematch.css` are the pages' side, `tests/scripts/web_rematch_check.js` runs them.

- **The game page** shows a strip under the picture: "The match is over", "Everybody can go back to the room together: same host, same colors, same map. Your seat is kept for you.", a chip for each player ("Maple · host · here", "Juniper · on the results screen") and the person's choice, two buttons: **Back to the room** and **Back to Ants & Uncles** (the front page). Nothing is chosen for a person who chooses nothing: the strip and the results screen stay until a button is pressed. The results screen of the game has the same two buttons (the new look: [`VIEW_AND_HUD.md`](VIEW_AND_HUD.md#the-new-look-of-the-results-screen); Classic art has Leave Game, which goes to the room): its **Back to the room** does what the strip's button does while the strip works (`window.antsLeaveToRoom`, asked by the game's `Application::back_to_room`; so a player in fullscreen, who cannot see the strip, is not sent to Home) and its **Back to Ants & Uncles** does what the strip's second button does (`window.antsLeaveToHub`, asked by `Application::back_to_hub`): the seat is given up at once with a Leave (the room keeps the others, its host passes as ever, bots stay) and the tab goes to the front page. When the game says that the match is over (`window.antsMatchOver`, the game's `Application::set_on_match_over`), the page reads the key of its seat before the game lets go of it and, two seconds later, holds the seat from the results screen with a game's Hello that asks for no color (an answer of the match itself, the rejoin flag of a match that the server had not ended yet, is let go of without a word and the seat is asked for again, three times at most); the button hands the code and the key to the front page of the same tab (its session storage) and opens `/?room=<code>`, which takes the seat back. A browser that refuses that storage keeps the tab where it is (no key goes into an address) and the strip says so. **A page that goes some other way gives its seat up with a Leave** (the Home button, a closed tab, a reload, and the results' Leave Game or "Back to the room" when there is no strip: before the link is there, with no key, with a seat that is not kept or with a storage that is refused): its color is open again. The Leave needs the strip's link, which exists from about two seconds after the results appear and only when the key could be read: a tab that is closed in those first seconds, a browser that blocks the storage or a tab that the browser discards keeps the seat until the host removes it or the three hours are over. In fullscreen the strip is under the picture: leave fullscreen to see it, or press a button of the results screen.
- **The front page** that comes back shows "Back from the match. Maple won with 2,040. Same room, same colors, same map." at the top, with **Stats and replay** (the match's page once the server lists its replay, found by the labels of its players there, "Green (Maple)"; else the list of matches), until START. Each player of the match is **Back in the room** or **Still on the results screen…**. The first player back leads, and the host of the match leads again on return (the others read "Maple is back, and is the host again."). **START waits** for every player who is not back: the leader reads "START waits for Juniper. You can wait, or press Remove on their color to start without them." under START, a press of START is answered by the room ("Juniper is not back from the match yet."), and **Remove** frees the color. No computer player and no empty color takes the place of a player who is not back.
- **What is not kept:** the seat of a player of the desktop game or of a phone's app (no button there: the color is open, and the player can join by the code like anybody once somebody is back), the seat of a player who left the match before its end (or whom it dropped), a match that ended without its results (everybody left, the room was closed: the code keeps the match), and the chat (the server keeps none). Nobody new can join while no player of the match is back, and a newcomer never leads while a seat is kept (so never removes one). A kept seat waits as long as the room lives, three hours at most; the room still goes a minute after nobody is in it (a results screen counts). A seat whose page went without a word stays kept until the host removes it or the three hours are over (the game let go of the key when the match ended, so nothing else can take it back), while a player of the match is in the room, back or on a results screen. When none is (somebody who joined by the link is alone with the kept seats, so nobody could lead), the kept seats end after the minute that a seat whose link ended gets, and the earliest person present leads. The front page's **Rejoin** of that match (a key that the game kept because its tab closed before the end) opens the game page, whose game is then back in the room, as a game: the color says "Still on the results screen…" and the leader reads "START waits for them" (the Room message does not say whether a game is the results screen or a game that came back, so the page cannot tell), although START takes it.

### Chat in the lobby

The people in a room talk before START in the **Chat** box under the colors (`web/front/lobby_chat.js` and `lobby_chat.css`; `web/lobby.html` only mounts it). The room's own chat is the game's ([`NETWORK_PORT.md`](NETWORK_PORT.md#chat-in-the-waiting-room)), so nothing of the server or of the network protocol changed (protocol 21): a page's line is the Chat message that the server already relays to everybody in the room, the sender too, with the sender's seat stamped; a player of the desktop game in the same room reads it in its chat box and the page reads theirs.

- **Where.** The room's tab of Home's chat box ([`HOME_CHAT.md`](HOME_CHAT.md#the-room-tab)): the box has two tabs while the page holds a room, **Ants & Uncles** (the site's chat) and **Room**, one press apart, with a dot on the tab that has news; on a phone it is the Chat view. A page whose Home parts did not load keeps the section in the room's panel, under the notice. It is there once the room has welcomed the page. Alone, the log says "You are the only one here. Send the link above, then say hello."; with company and nothing said, "Nothing said yet. Say hello: everyone in this room will see it." A line that arrives while the box is out of view (under the window, or under the START bar of a phone) is also the page's toast, "Sam: hello": the toast is for a stranger's text, so a line is cut to 60 characters (with an ellipsis), a word with no blank wraps inside the frame (the toast is as wide as its text allows, up to 520 px or 92% of the window), the toast takes no tap (a card or a Remove button under it gets it), and there is at most one chat toast in 4 s, so that one talker cannot keep it up (the log has every line).
- **A line** is 1 to 100 printable ASCII characters, the game's chat entry. What the game's font cannot show (an accent, a smiley) is left out as it is typed, with a line that says why; blanks at the ends are cut off and an empty line sends nothing. Enter or Send says it, and the field keeps the focus, so a phone's keyboard stays up. The line is drawn when the room sends it back (the room's word that it was heard), as "Name:", a blank and the text (a copy of the log reads "Sam: hello"), the name in the color of the seat (the accents of the cards); a seat that has no name yet is "Seat N", as in the game's own box. Every name and line is set as text, never as markup.
- **The pace** is a little UNDER the server's: four lines at once, then one every 1.25 s (`LobbyClient.say` and `BUDGETS.chat` in `web/front/lobby_net.js`; the server's own is `kChatBurst` 5 and `kChatPerSecond` 1). The room drops a line beyond its pace without a word (the sender sees nothing), and a connection that goes on is thrown out, and the room counts the moment at which it HANDLES a line, not the moment at which it was said: a page that paced itself at exactly the server's rate lost a line whenever the network (or the server's own loop) delayed one line and not the next (seen on the macOS CI). So the page keeps a line in reserve and 250 ms per line, and a line may be handled a second sooner than the page's pace says and is still heard. **Every other request of the page keeps the same margin** (`BUDGETS`: a burst one smaller than the server's and 0.8 of its rate): a color move and a plan go 5 at once and then 3.2 a second (the server's own: 6 and 4), a name and a removal 2 at once and then one every 1.25 s (3 and 1). They went at exactly the server's rate before, and a rename or a plan that was handled early was dropped without a word, so the change vanished from the screen. No request waits for the room's answer before the next, so the margin is what keeps them heard: one request that is held up while the ones after it arrive on time is still heard when the hold-up is up to about a third of a second (a color move, a plan) or one and a half seconds (a name, a removal, a line); a longer one can lose a request, and then the screen shows what the room has. A line that the page does not take stays in the field, and the hint says "A little slower, please. Your line is still here." The field is shut (read-only, not disabled: it keeps the focus, so a phone's keyboard stays up when the link drops), and says why, while the link is down ("Chat is back when you are in the room again.") and while START waits ("Opening the game…"); the box is dimmed with the cards when the link is down, but the names keep a contrast of 4.5:1 or more on the dimmed log.
- **A line that the room does not say back.** The client's `say()` is true as soon as the socket took the bytes; a stalled uplink, or a link that drops with the line in it, loses the line without a word. So a line stays pending until the room says it back. With no echo in 3 s, or when the link drops first, the hint reads "Your last line may not have arrived. It is back in the field." and the text is back in the field to be sent again (when the field already holds other text, the hint holds the line: "Your last line may not have arrived: hello"); an echo that comes late takes the hint away. This is the page's mitigation, not a guarantee: the page cannot know that a line arrived, only that the room said it back.
- **The small lines of the system** ("Sam joined as Red.", "Sam left.") are made by the page from the room's changes that it sees anyway: they are sent to nobody, smaller and muted. The page's toasts for a move or a swap stay as they were.
- **What it does not do.** The lines live in the page: the room does not replay them, so a reload starts an empty box, and nothing is stored. START takes the pages to the game page and the lines end there: they are not in the countdown card's chat or the match's chat log, which a game that takes a seat over starts for itself. The game's option "Participate In Chat" belongs to the match (the page cannot read it); the box is always on. There are no private lines, no moderation beyond the pace, and a computer player does not chat.
- **The composer** is the front page's chat composer (`web/home/talk.js` and `talk.css`, loaded once after the first paint and shared with Home's dock: [`HOME_SCREEN.md`](HOME_CHAT.md#emoji-and-voice)): one row with the field, the microphone and Send at the right, 8px corners, two rows when the words wrap, Enter sends. The room's line is printable ASCII, so the emoji button is left out here (the picker's characters are not ASCII and the room would drop them); the microphone types what is heard into the field and the line is cleaned when it is sent, as for typing, within the 100 characters. A page where the shared script did not come has the field and Send only.
- **The Room has no site footer.** The recording notice ("Online matches are recorded. Recordings are kept for up to 90 days. Results and names are kept for good and are public.") is at the bottom of the room's panel, the Menu has the links, the live numbers and the version, and the Legal page is one of its links.
- **A phone.** The field is 16 px (the browser does not zoom into it) and a finger tall, the log is shorter, and the field asks the browser for room (`scroll-margin-bottom`) so that the START bar that sticks to the bottom of the screen does not cover it when the keyboard has shrunk the window.

### The notices

A strip at the top of the page says in one line what the page changed for you or what did not work: green when the page changed something (a room of your own after a link to a room that was full, running or closed to you; the new host), gold when something did not work (the server is full, the connection is lost, a new version of Ants is out, the server's own sentence for a map that could not load or a start that failed). While the connection is lost the room goes grey and read-only, START! says "Reconnecting…", and the color is kept for a minute; the page rejoins by itself with its key. If the page cannot reach the server at all, a gold strip says "Cannot reach the game server. Check your connection; trying again…". The sentences are `TEXT` in `web/front/lobby_rules.js`; the ones that start with the server's own words repeat what the server said.

### Your name

Everybody else plays as a guest: the name that was typed on the front page, kept in this browser (`ants.guestname`), with " (Guest)" after it, else "Guest" and six digits (`Guest 482173`), made once and kept in this browser (`localStorage`, `ants.guest`: a random number and nothing else; a login and a log out never change it; a browser that keeps nothing has it for the page). ### Rejoin your match (CODE)

While this browser holds a fresh key of a seat on this site's game server, a strip stands at the top of the front page, above its header, with the line "Your match in room CODE is still running: go back to your seat." and one button, **Rejoin it**. Without such a key nothing of it is shown.

- The game page keeps a key for every seat that it plays, for three hours, and lets go of it when the match ends, the seat is dropped or the player leaves.
- The button takes this tab to the game page of that seat (the newest, when there are several). The game page finds the key itself: it is in no address, text or log. The match goes on where it was. The line shows the code as a screen does (`k7m 2xq`); the address that the button opens has the plain code, the seat and no create block, so a match that has ended is not made again by it.
- The exceptions: the others voted to go on without you (they may after 30 seconds), or the pauses of the match reached their cap, 30 minutes (10 in a demo room). Then the game says so. The rules of a held seat are in [`MULTIPLAYER.md`](MULTIPLAYER.md), "Lag, silence and drop-outs", and [`NETWORK_PORT.md`](NETWORK_PORT.md#the-behaviour-that-is-decided) (the vote and the cap); the options are in [`SERVER.md`](SERVER.md#reconnect).

The page has no script but the bar's; the image build stamps the version and the build into its bar for the last line of the Menu (the three `data-` attributes of [the bar](SITE_NAV.md)).

## Starts at once, and the sound follows your first click or key

- There is no start button. The game runs as soon as its data has downloaded (a loading card shows the download and goes away by itself); the original's own loading screen and quick help follow as always.
- Browsers let a page make sound only after you have done something on it, so the music and the sound effects begin with your first click, key press or touch on the page. The page keeps trying until the browser lets the sound run (Safari is the strictest; what each browser needs is under "Sound and the autoplay rules" below).
- The page downloads the game's data (19.3 MB) itself and tries again, up to three times, when a download fails (a browser's cache can refuse a download). If every try fails, if a file of the game (`index.js`, `index.wasm`) cannot be loaded, if the game never starts, or if the download is a web page instead of the data (a captive portal), a card with a **Reload** button replaces the loading screen.
- A box of the browser's own ("Leave the game and go back to the menu?", the copy of a recording's link) stops the page until you answer it, so the page pauses the game's sound while it is open and resumes it after; without that, the browser plays the last piece of sound over and over (`antsQuietly` in `web/shell.html`, run by `tests/scripts/web_quiet_dialog_check.js`).

**Sound and the autoplay rules.** A browser lets a page make sound only after the person has done something on it, so the game's Web Audio context (SDL's, `Module.SDL2.audioContext`, opened when the game starts) begins suspended and the game's sound and music begin the moment it is resumed; the game itself does not wait for it, and there is no start overlay any more (the page used to hide the game behind a card that said "Click anywhere to play!" until a click). SDL's own Emscripten audio already resumes the context at the first `keydown`, `mousedown` and `touchstart` (`autoResumeAudioContext`: once each, on the document and the canvas); the old page's own tries did nothing (it looked for a global `SDL2`, which does not exist, and made a second context that played nothing). `web/shell.html` now keeps trying until the context really runs (no `once`: a press that grants nothing, such as the Esc key or a shortcut of the browser, or a press before the context exists, would use the attempt up), on `pointerdown`, `mousedown`, `click`, `touchend` and `keydown`, and takes its listeners off as soon as the context runs; a context that stops later is resumed by the next press (`statechange`, `visibilitychange`). What each browser needs: *Chrome and Edge*: a context created before any user activation starts suspended; `resume()` works after a user activation (`mousedown`, `pointerdown` of a mouse, `pointerup` / `touchend` of a finger or a pen, `keydown` of a key that is not Esc or a shortcut of the browser), and the activation is sticky: after the first press anywhere on the page a context created later starts running. *Firefox*: the same rule (a suspended context, `resume()` in an input event: click, keydown, touchend; the person may also allow audio for the site, then the context runs at once). *Safari* (macOS and iOS): the strictest: `resume()` must be called inside the handler of a gesture (`click`, `touchend`, `keydown`), it is not sticky, `touchstart` does not count on iOS, a context that a phone call or the lock screen interrupted (`interrupted`) needs a new press, and the ringer switch silences Web Audio on an iPhone. The built-in browser lets pages play at once (its context was `running` before any press), so the check there exercised the page's logic with a real context that was suspended by hand: a trusted click resumed it, a second suspension was resumed by the next click, with the context running the listeners were gone (no `resume()` call), and a press while no context existed raised nothing and the next press resumed it. The keyboard focus: the canvas takes it when the game is ready, and again at the first press inside the game.

## A network match keeps playing in a hidden or minimised tab

- A browser stops drawing a page that you cannot see and slows its timers. Every message of the game server still wakes the game, which plays its turns without drawing anything and without sound or music. So the match goes on at the normal speed, nobody is told that you lag (`<your name> is lagging`), and you find it up to date when you come back (the music of a match that begins or ends meanwhile follows then). A single game (no network) simply waits while the page is hidden, as the desktop game does when minimised.
- A server that stops answering is noticed after 10 seconds of real time, a hidden page included (the page's timer is a Worker, which the browser does not slow): a seat hidden for minutes noticed a paused server at +10 s, as a shown one did.
- **Limits**: a computer that sleeps, a phone that locks its screen or leaves the browser, and a tab that the browser freezes stop the page (a frozen tab loses its connection when it wakes up). Since v0.6.0 the server holds such a seat and pauses the match; the game reconnects with the seat's key, or **Rejoin your match** takes the seat back. A seat whose page stays connected but runs no turns is still called lagging after 3 seconds and dropped after 30 ([`MULTIPLAYER.md`](MULTIPLAYER.md), "Lag, silence and drop-outs").
- No automated test covers this code, which exists only in the web build. The manual check and the opt-in script `tests/scripts/test_web_hidden.sh` are in [`NETWORK_PORT.md`](NETWORK_PORT.md#the-browser-as-a-client-hidden-tabs-and-sound-v0096), "The browser as a client: hidden tabs, and sound".

## The screen stays on

- The game page asks the browser to keep the screen awake (the Screen Wake Lock, `navigator.wakeLock`, as a video page does) while a match is played, from the countdown card to the results, and while a recording plays or a live match is watched (`web/wake_lock.js`, called by `web/shell.html`). A paused recording, its end and a file that cannot be shown do not hold it. The lock is let go on pause, at the results and when the page is left, and asked for again on play, on "Watch again", for the next match and when the tab is shown again (the browser drops it while a tab is hidden). The power button still locks a phone ([the limits of a hidden tab](#a-network-match-keeps-playing-in-a-hidden-or-minimised-tab)).
- A browser without the Screen Wake Lock (iOS before 16.4, and others) is left as it is: no message, no stand-in. A request that the browser refuses (a low battery, a power saver, a policy) or never answers is dropped without a word and asked again after 15 seconds, or when the tab is shown. The game never waits for it and nothing is drawn. Tests: [`TESTING_PYTHON.md`](TESTING_PYTHON.md).

## Your own orders show at once in a network match

- The game can run a second engine next to the match's own (the confirmed one, which the host's turns, the server's referee and every hash keep exactly as they were). An order is run on it in the same call and the screen shows it, a few ticks ahead, so the ants answer a click as they do in a game of one machine instead of one round trip, one seal and one jitter buffer later. The corner's `delay` shows what the click feels.
- **It is on by default.** When another player's order arrives, the ants it concerns slide to where the engine has them, never faster than an ant walks, instead of jumping. `?prediction=off` on the game page's address switches it off, as the game's `--no-prediction`; a game on one computer never predicts. Once on, it switches itself off for a while (ten seconds, twice as long each time) when its work takes too long on a slow device, and it is off in a hidden tab, in a pause and while the "Get ready" dialog is up.
- More: [`MULTIPLAYER.md`](MULTIPLAYER.md), "Prediction of your own orders"; the design: [`NETWORK_PORT.md`](NETWORK_PORT.md#prediction-of-ones-own-orders-predictionhpp-cue_routerhpp-netgame-applicationview_sim).
